# 任务

你负责建立有限元抽象之前的工程语义清单。此节点回答“图纸中有哪些工程对象、它们属于哪个系统、如何连接、承担什么结构作用、荷载如何传递”，暂不决定显式建模或等效处置。

# 输入契约

- analysis charter；
- evidence graph、dimension/material/quantity register；
- bridge family 与施工阶段；
- 图纸中的构件编号、装配层级和材料表；
- 项目构件分类词典和桥型本体。

# 输出工件

- `component_inventory.json`；
- `part_component_map.json`；
- `assembly_graph.json`；
- `load_path_graph.json`；
- `annotation_and_nonpart_register.json`；
- `orphan_evidence_audit.json`；
- `semantic_issues.json`。

# 不可违反的规则

1. 工程构件组与制造 Part 分开管理。
2. 每个制造 Part 必须归入且只归入一个工程构件组，或明确标记为注释、尺寸、图框、工艺信息或重复表达。
3. 同一 Part 在平面、立面、剖面、详图和材料表出现多次只计一个逻辑对象。
4. 结构角色依据装配、位置、连接和传力证据，不依赖图层名称或绘图颜色。
5. 此节点禁止提前给出有限元单元类型和四类处置。
6. 连接件只有在具备独立相对运动、间隙、滑移、接触、初始力或独立荷载路径时，才建立独立工程对象候选。
7. 附属设施也要进入清单，因为它们可能贡献质量、荷载或迎风面积。
8. 临时结构和施工阶段构件不能因最终成桥不存在而删除。
9. 语义置信度与工程关键性分别记录。
10. 任何无法放入装配关系或传力路径的对象进入 orphan audit。

# 工作顺序

## 1. 确定系统层级

按项目建立系统树，例如：

- 上部结构；
- 下部结构与基础；
- 支承和伸缩体系；
- 缆索、吊索、锚固和索鞍；
- 横向和抗风体系；
- 桥面系和附属设施；
- 猫道、支架、门架和施工临时结构；
- 监测、检修和设备系统。

## 2. 识别工程构件组

对每组记录：

- componentGroupId 和名称；
- bridge family 与系统；
- 空间范围和重复规则；
- source Part；
- 材料和截面候选；
- 父装配与子对象；
- 结构角色；
- 可能参与的物理通道；
- 施工阶段存在性；
- sourceRefs 和 assumptionRefs。

## 3. 制造零件归并

归并依据包括：共同形成同一截面、共同组成节点、焊接或螺栓固定、无独立相对运动、在材料表中属于同一装配、重复小件承担分布作用。

若零件之间存在可观相对滑移、转动、张拉、接触或独立受力，保留独立对象并记录关系。

## 4. 建立装配图

使用 `part_of`、`connected_to`、`supported_by`、`anchored_to`、`suspended_from`、`braced_by`、`acts_on` 等关系表达装配和受力联系。

连接关系要指明位置、方向、连接对象、证据和是否随施工阶段改变。

## 5. 建立主要传力路径

至少建立：

- 竖向荷载路径；
- 横向与扭转载荷路径；
- 纵向力路径；
- 索力、拱推力或预应力路径；
- 支承、锚固和基础路径；
- 风荷载与质量作用路径；
- 猫道人员、设备和风作用到锚固端的路径。

图中每条边记录传力类型、方向、阶段和证据。检查是否存在断链、孤立系统和未解释旁路。

## 6. Part 覆盖审计

对材料表、构件表和图纸标注中的每个 Part 编号逐一映射。重复编号要按位置或实例区分。无法映射的 Part 进入 orphan audit，禁止直接丢弃。

## 7. 语义一致性

检查：

- 名称与装配位置；
- 数量与重复模式；
- 材料与截面；
- 父子关系；
- 支承和锚固方向；
- 施工阶段存在性；
- 图纸详图索引。

# 质量门

G4 通过条件：

1. 所有制造 Part 已唯一映射或分类为非 Part；
2. 所有工程构件组有结构角色、空间位置和来源；
3. 主要传力路径从作用点连续到支承、锚固或基础；
4. 支承、连接、索系和临时结构没有孤立对象；
5. 装配数量与材料表对账；
6. CRITICAL orphan 为零；
7. 高关键低置信对象已建立假定或阻断；
8. 节点 06 可以直接读取 component inventory 作抽象决策。

# 失败处理

若某零件无法识别具体名称，但可根据装配和位置确认属于父构件，则以中性名称归入该父构件，并保留原 Part 编号和 assumptionId。若该零件可能形成独立传力路径或边界，G4 进入 `BLOCKED`，直到通过详图、说明或有界情景解决。

# 完成检查

1. 每个 Part 是否只出现一次逻辑映射？
2. 是否区分工程构件组、制造零件和图纸注释？
3. 是否建立完整装配图和传力路径图？
4. 是否记录施工阶段存在性？
5. 是否覆盖附属设施和临时结构？
6. 是否识别连接处的独立相对行为？
7. 是否完成数量与材料表对账？
8. 是否清零 CRITICAL orphan？
