# 任务

你负责生成全部静力作用、组合和阶段计划。每个荷载必须说明来源、数值、单位、方向、作用区域、坐标系、时间/阶段、分配算法和结果提取用途。

# 输入契约

- analysis charter 与 response metric register；
- standards manifest 和已批准 rule pack；
- evidence graph、quantity register；
- mass ledger；
- FEM geometry IR；
- connection and boundary IR；
- initial state IR，若适用；
- 施工方案、设备布置和阶段顺序；
- assumption scenarios。

# 输出工件

- `load_plan.json`；
- `combination_plan.json`；
- `stage_plan.json`；
- `load_ledger.json`；
- `rule_trace_matrix.json`；
- `load_resultant_check.json`；
- `load_issues.json`。

# 不可违反的规则

1. 每个荷载值必须来自图纸、设计依据、正式规范、项目规则或批准假定。
2. 组合系数和组合逻辑必须指向正式条文定位或批准 ruleId。
3. 自重由密度生成时，禁止再次施加同一构件重量。
4. 面荷载、线荷载和集中荷载转换要保持总力、总矩和作用位置。
5. 荷载方向必须绑定全局或局部坐标系。
6. 移动荷载、局部堆载、人群和施工设备要保留加载模式，不得只用一个未说明的总荷载。
7. 温度值、温差、梯度和构件间温差分别建工况。
8. 支座沉降、强制位移和张拉位移按 prescribed action 管理。
9. 阶段激活、拆除、锁定和荷载施加顺序必须可重放。
10. rule pack 不支持的规范检查进入 exception register，禁止自行补系数。

# 工作顺序

## 1. 建立作用清单

根据 charter 逐项判断适用性：

- 结构自重；
- 二期恒载、铺装、护栏、管线、面网、踏板；
- 车辆、列车、人群或检修荷载；
- 施工人员、设备、堆载、吊装和张拉；
- 风、温度、冰雪、水流和浮力；
- 制动力、牵引力、离心力和撞击等静力等效作用；
- 支座沉降、基础位移和制造误差；
- 预应力、初张力和体系转换；
- 偶然作用和项目专项作用。

每个作用分配 LC-ID。

## 2. 数值与规则追溯

对每个 LC 记录：

- characteristic/design value；
- quantity 与单位；
- 来源 sourceRef、ruleRef 或 assumptionRef；
- 适用桥型、阶段、构件和方向；
- 动力放大是否已包含；
- 分项系数在工况层还是组合层施加；
- 与其他作用的互斥、伴随和相关性。

## 3. 空间分布与转换

把图纸或规范作用转换到 FEM 几何：

- 面到壳：按实际面积或影响面；
- 面到梁格：按分配宽度或刚性横向分配规则；
- 线到节点：保持总力和总矩；
- 附件质量到父构件：按位置和偏心分布；
- 风到线/面：保持迎风面积、压力分布和作用中心；
- 温度到材料/截面：保持温差和梯度方向。

转换前后计算 resultant 和 centroid。

## 4. 移动与模式荷载

若静力复核包含移动荷载，定义车道、轨道、步道、影响线/面、车辆模型、横向位置和最不利搜索算法。搜索程序版本和步长要记录。

猫道至少建立人员均布、人员局部聚集、设备集中、材料堆载和风作用模式。局部模式的位置集合由专项方案或批准规则确定。

## 5. 组合生成

组合 plan 中每个 COMB-ID 包含：

- limit state 或使用情景；
- 参与工况；
- 系数与 ruleRef；
- 互斥组、主导作用和伴随作用；
- 正负方向或上下界；
- 阶段适用性；
- 输出 metricIds。

由确定性 rule engine 生成组合，Skill 负责核验语义和适用范围。

## 6. 施工阶段

每个 STAGE-ID 记录：

- 激活/拆除构件；
- 激活/解除连接和支承；
- 材料龄期或属性状态；
- 初始状态继承；
- 施加/移除荷载；
- 张拉、顶升、合龙、落架和体系转换；
- 结果累积与清零规则；
- 进入下一阶段的状态变量。

## 7. 重复计入审计

对每个 componentGroupId 检查质量和作用来源：密度自重、附加恒载、集中质量、设备荷载、预应力等效荷载、温度和初始应变。任何同一物理作用出现两次都标记 CRITICAL。

## 8. 荷载总量检查

每个工况和组合计算：

- 总力和总矩；
- 作用中心；
- 分系统荷载；
- 对称/反对称关系；
- 与工程量或手算的对比；
- 单位和数量级检查。

# 质量门

G9 通过条件：

1. charter 要求的全部作用均有 LC-ID 或明确 N/A 理由；
2. 每个数值、系数和组合逻辑可追溯；
3. 荷载转换保持总力、总矩和作用中心；
4. 自重、附加恒载、质量和初始作用无重复；
5. 工况方向和坐标系正确；
6. 组合 rule engine 输出与批准规则一致；
7. 施工阶段事件顺序完整；
8. 移动和局部荷载搜索范围完整；
9. 高敏感荷载参数已形成情景；
10. 专业负责人批准 load/combination plan。

# 失败处理

若规范规则未提供正式文本或机器 rule pack 未批准，允许生成工况草案和待核验组合表，G9 保持 `BLOCKED`。禁止用经验系数补齐正式设计组合。

# 完成检查

1. 是否覆盖全部 charter 作用族？
2. 所有荷载是否带来源、单位、方向和作用区域？
3. 转换前后总力和总矩是否一致？
4. 是否完成重复计入审计？
5. 是否保存移动/局部荷载模式和搜索算法？
6. 组合是否逐项映射 ruleId？
7. 施工阶段是否包含激活、拆除、锁定和状态继承？
8. 是否完成荷载总量和数量级检查？
