# 工程 Skill 质量标准

每个新增或修订 Skill 必须满足以下结构，才能进入 workflow。

## 1. 触发边界

frontmatter 的 description 同时写明适用场景、触发条件和职责边界。不能用泛化描述让多个 Skill 同时争夺同一任务。

## 2. 输入契约

逐项列出必需工件、schema version、允许状态、单位政策、坐标、sourceRef、assumptionRef 和上游 gate。缺少任一关键输入时给出明确阻断逻辑。

## 3. 输出契约

输出采用统一 envelope，业务字段具有稳定 ID、来源、单位、状态和下游接口。报告文本只能作为结构化工件的视图，不能成为唯一正式输出。

## 4. 工程不变量

列出任何实现都不能破坏的物理与治理规则，例如传力路径连续、质量不重复、荷载总力/总矩守恒、索只受拉、标准规则有正式来源、原始结果不可修改。

## 5. 有序算法

工作顺序按“准备—计算—检查—封装”展开。每一步明确使用哪些输入、产生哪些中间量和执行哪些确定性检查。禁止把关键判断藏在自由叙述中。

## 6. 质量门

Gate 条件必须可以由数据或审批直接判断。每项条件包含 metric、阈值、证据和失败状态。`PASS_WITH_BOUNDS` 需要全边界计算，`BLOCKED` 不能被下游绕过。

## 7. 失败处理

按失败来源返回首个责任节点，禁止在后处理层修饰问题。允许的重试序列、最大次数和可变字段需要预先批准。

## 8. 独立验证

关键 Skill 至少配置单元测试、黄金样例、性质测试或独立方法。输出字段、符号、单位和边界情况均应进入测试。

## 9. 审批与变更

需要专业判断的结论写明审批角色。签名绑定工件哈希。Skill、schema、rule pack 或工具链变化要记录版本并运行回归。

## 10. 禁止项

- 无来源数值；
- 裸数值跨节点传递；
- 未声明的求解器默认值；
- 静默降级物理特性；
- 用一个综合评分覆盖关键失败；
- 运行成功替代物理或数值验证；
- 覆盖旧工件；
- 使用含糊占位语句作为正式结论。
