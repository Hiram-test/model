# 首个真实项目运行手册

## 项目选择

首个试点优先选择资料完整、已有人工审核模型和最终计算书的桥梁或猫道项目。将既有成果仅作为独立对比基准，自动化流程仍从原始资料重新建立证据链。

## 准备目录

```text
project/
  request/
  sources/original/
  sources/standards/
  approvals/
  runs/
  releases/
```

原始资料上传到 `sources/original/` 后立即计算哈希并锁定。任何修订以新文件进入，不覆盖旧文件。

## 首轮目标

首轮只要求完成：

- N01–N06 的证据、构件与抽象闭环；
- 一套受限用途的 N07–N16 静力模型；
- 三个独立控制量：总反力、一个位移、一个主构件内力或索力；
- 一次参数边界分析；
- 一份可复现发布候选。

局部实体、疲劳、动力、稳定、风致振动、地震和复杂材料非线性只有在 charter 明确纳入且工具链已验证时才启用。

## 运行步骤

1. 复制 `examples/project_manifest.example.yaml` 与 `examples/analysis_charter.example.yaml`；
2. 填写结构阶段、用途、输出指标、规范文件和审批角色；
3. 运行 N02，确认文件数量、修订、xref 和标准哈希；
4. 运行 N03–N04，并由工程师只处理 CRITICAL 冲突；
5. 运行 N05–N06，审查 component inventory、load path 和四类处置；
6. 冻结 G5 后生成 FEM-IR；
7. 完成属性、边界、初态、荷载和网格；
8. 运行 N13 的求解前检查，所有严重项关闭后才调用 solver；
9. 运行 N15 的平衡与收敛；
10. 运行 N16 的响应与规则复核；
11. 独立检查人运行 N17；
12. N18 生成 release candidate，并在干净环境执行 smoke test。

## 人工对比记录

将自动化结果与既有人工模型按以下层级比较：

- 输入事实：跨径、标高、材料、截面、边界、荷载；
- 模型统计：节点、单元、质量、重心、约束；
- 静力结果：总反力、控制位移、构件内力、索力；
- 工程结论：控制组合、利用率、限制和例外。

发现差异时先归因到事实解释、抽象、模型实现、数值解或结果规则，禁止直接校准到旧模型数值。

## 试点验收

试点完成需满足：

- 19 个 Skill 通过 lint；
- 所有核心工件通过 schema；
- 关键 source/evidence/model/claim 追踪覆盖率为 100%；
- 求解前、解验证和独立复核 gate 通过；
- 自动结果与解析或独立基准在预设容差内；
- 参数边界内工程判定稳定；
- 发布包可在干净环境复现最小控制 metric；
- 工程师能根据 issue 定位责任节点并完成一次变更重跑。
