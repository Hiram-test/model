## 节点 00 · `bridge-fem-workflow-orchestrator`

来源：`skills/00-bridge-fem-workflow-orchestrator/SKILL.md`

---
name: bridge-fem-workflow-orchestrator
description: >
  编排桥梁或猫道从原始图纸接入、工程语义化、有限元建模、静力求解、验证、规范复核到发布归档的完整工作流。
  当任务需要跨多个 Skill 自动运行、评估质量门、管理条件分支、重试、审批、变更影响和工件追溯时使用。
  本 Skill 只负责控制流程和验证数据契约，不代替各专业节点作出具体工程计算结论。
---

# 任务

你负责运行 `workflow.yaml` 所定义的桥梁 FEM 工作流，确保每个节点只消费已冻结且通过质量门的上游工件，并输出可追溯、可重放、可阻断的运行记录。

工作流的目标是形成一个可审计计算链：同一组冻结输入、同一工具链版本和同一审批状态应产生可比较的输出；任何输入、规范、假定、脚本或求解器变化都要形成新 run。

# 输入契约

必须读取：

- `project_manifest`：项目 ID、run ID、内部单位制、坐标约定、工具目标和审批角色；
- `project_request`：用户本次要求的模型用途与交付物；
- `source_files`：原始图纸、设计说明、专项方案、材料表、计算原则、规范文本和既有模型；
- `workflow.yaml`：节点、依赖、条件、产物和 gate；
- `schema_registry`：所有节点产物的数据契约；
- `tool_registry`：允许使用的解析器、几何内核、求解器和版本。

若用户要求从某个中间节点继续，必须先核验其上游工件哈希、schemaVersion、gate 状态和工具链版本。

# 输出工件

至少输出：

- `run_plan.json`：本次激活节点、条件分支、并行组和审批点；
- `task_packets/`：每个节点的冻结输入清单、输入哈希和输出路径；
- `gate_ledger.json`：所有 gate 的状态、检查值、证据和审批；
- `issue_register.json`：CRITICAL、MAJOR、MINOR、INFO 问题；
- `artifact_lineage.json`：工件依赖图与哈希链；
- `run_summary.json`：完成节点、阻断节点、可发布范围和下一步动作。

# 不可违反的规则

1. 禁止跳过任何被激活节点的强制 gate。
2. `BLOCKED` 工件不得进入下游，即使下游程序能够读取。
3. `PASS_WITH_BOUNDS` 的所有情景、假定和限制必须原样传播。
4. 节点失败后不得覆盖旧工件；新尝试产生新 artifactId。
5. schema 错误可以在不改变工程输入的前提下重生成；工程输入变化必须建立新 run 或新分支。
6. 求解器不收敛时，只能执行已在节点 12 批准的数值控制序列；不得自动修改材料、边界、荷载、连接、初张力或网格物理含义。
7. 任何工具替换都要记录工具名、版本、配置和替换原因。
8. 审批记录必须包含角色、人员、工件哈希、批准范围和时间。
9. 同名文件、同名对象和同名工况不能作为唯一身份；所有引用使用稳定 ID。
10. 运行日志、标准输出、标准错误和命令行参数完整保存。

# 工作顺序

## 1. 初始化 run

校验 projectId、runId、单位制和坐标约定。计算所有原始输入哈希，创建只读输入快照。若 runId 已存在且输入哈希不同，立即阻断并要求新 runId。

## 2. 解析工作流

读取节点依赖，执行拓扑排序。根据 `analysis_charter` 的桥型、分析类型、是否需要初始状态、是否包含施工阶段等字段激活条件节点。

在节点 01 尚未完成前，只允许执行节点 02 的文件完整性预扫描，不允许生成正式模型工件。

## 3. 生成任务包

每个任务包包含：

- 节点 Skill 名称与版本；
- 直接上游 artifactId 和 sha256；
- 允许读取的原始文件；
- 允许调用的工具及版本；
- 输出 schema；
- gate 检查项；
- 资源限制与超时；
- 审批要求。

禁止让节点读取未列入任务包的“最新文件”或工作目录中任意同名文件。

## 4. 执行与校验

节点结束后按以下顺序检查：

1. 文件存在且可解析；
2. envelope 与业务 schema 合法；
3. projectId、runId 和上游哈希一致；
4. 必备对象都有 sourceRefs 或 assumptionRefs；
5. gate 检查完整；
6. 状态符合问题分级；
7. 审批满足要求。

只有全部满足时，工件才进入 artifact registry。

## 5. 重试与回退

- schema 或格式错误：同节点最多重生成两次，工程输入保持不变；
- 解析器失败：可切换已批准的二级解析器，必须保留两套结果和差异报告；
- 工程证据冲突：进入 `BLOCKED`，由上游节点修订；
- 求解器失败：按已批准数值序列重试，每次生成独立 run record；
- 结果验证失败：回到最早导致失败的节点，不在后处理层修饰结果。

## 6. 并行执行

只有没有数据依赖且共享资源可隔离时才并行。例如独立手算、第二求解器和报告图表生成可以并行；主模型求解前的几何、属性、边界和荷载节点必须按依赖完成。

## 7. 变更影响

收到修订图纸、规范、假定或模型要求后：

1. 计算新旧哈希差异；
2. 沿 artifact lineage 找到首个受影响节点；
3. 标记全部下游工件为 superseded；
4. 只重跑受影响子图；
5. 无条件重新评估 G11、G13、G15 和 G16。

## 8. 发布判断

只有 G0 至 G16 中所有激活 gate 均为 `PASS` 或满足发布条件的 `PASS_WITH_BOUNDS`，且审批完整，才生成 release manifest。任何 `BLOCKED` 都要在 run summary 中列明阻断原因和所需补充资料。

# 质量门

`G-ORCH` 必须同时满足：

- 工作流无循环依赖；
- 每个激活节点存在对应 Skill 和 schema；
- 每个工件的上游哈希链闭合；
- 没有 `BLOCKED` 工件被下游消费；
- 所有工具版本已固定；
- 所有强制审批已绑定到具体工件哈希；
- 旧工件没有被覆盖；
- release manifest 可重放到同一节点配置。

# 失败处理

若无法确定某个文件属于哪个版本，先由节点 02 生成 revision conflict，不得按文件修改时间自动选取。若某个 Skill 缺失，工作流进入 `BLOCKED`，并精确输出缺失节点的输入、输出和 gate 要求。

# 完成检查

1. 是否为每个节点生成冻结任务包？
2. 是否验证所有工件 schema 和上游哈希？
3. 是否传播全部有界情景和限制？
4. 是否阻止任何 `BLOCKED` 工件进入下游？
5. 是否保留每次重试的独立记录？
6. 是否对工具替换和求解设置变化留下审计？
7. 是否重新评估强制集成 gate？
8. 发布包是否能说明允许用途、限制和审批人？

## 节点 01 · `bridge-analysis-charter`

来源：`skills/01-bridge-analysis-charter/SKILL.md`

---
name: bridge-analysis-charter
description: >
  在桥梁或猫道建模前冻结模型用途、桥型、分析范围、施工阶段、适用规范、控制响应、验收标准、允许用途和风险等级。
  当项目刚启动、分析目标发生变化、规范版本调整或既有模型需要重新界定用途时使用。
---

# 任务

你负责建立整个计算链的分析章程。章程决定后续哪些图纸事实必须提取、哪些构件需要建模、采用何种物理、需要哪些荷载和组合、结果如何判定，以及模型可以支持哪些工程决策。

# 输入契约

必须读取：

- 用户目标、项目阶段和交付要求；
- 桥梁或猫道的总体说明、结构体系和施工方案；
- 项目计算原则、设计依据、审查意见和既有模型说明；
- 正式规范文本或项目批准的规则包；
- 目标求解器与可用计算能力；
- 已知风险、关键构件和监测或试验数据。

缺少正式规范文本时，可以建立待填充的 standards manifest，gate 保持 `BLOCKED`。禁止凭记忆写入条文号、组合系数或限值。

正式依据、用户要求和项目计算原则均使用 sourceRef 或批准记录定位；章程不得依赖无法追踪的口头信息。

# 输出工件

- `analysis_charter.json`；
- `standards_manifest.json`；
- `response_metric_register.json`；
- `approval_matrix.json`；
- `scope_exclusion_register.json`。

# 不可违反的规则

1. 建模用途必须具体到结构阶段、作用类型、响应和决策。
2. 每项验收标准必须有来源、数值、单位、适用对象和比较方向。
3. 规范按 jurisdiction、编号、名称、版本、勘误、局部修订、正式文件哈希和采用日期冻结。
4. 设计作用、组合、材料抗力和构造检查分别登记，禁止混成一个模糊“符合规范”。
5. 允许用途和排除用途必须同时给出。
6. 静力、稳定、模态、风、地震、施工阶段、局部应力和疲劳是不同分析用途，不能互相隐式替代。
7. 风险等级越高，独立复核和审批要求越高。
8. 模型范围变化要生成新 charter 版本，并触发变更影响分析。

# 工作顺序

## 1. 定义结构对象

确定结构族：梁桥、箱梁桥、钢—混组合桥、拱桥、桁架桥、斜拉桥、悬索桥、下部结构、基础、猫道、支架、临时索系或混合体系。

记录桥轴、跨径、支承体系、材料体系、当前施工阶段和主要结构转换。

## 2. 定义 intended use

使用下列句式形成用途：

“模型用于【项目阶段】下，计算【作用或组合】引起的【响应】，支撑【工程决策】，适用对象为【结构范围】，结果精度要求为【阈值或等级】。”

每个用途分配 `useCaseId`。一个模型可以有多个用途，但每个用途必须有独立验收标准。

## 3. 定义物理范围

逐项决定：

- 线性或几何非线性；
- 材料线性或非线性；
- 小变形或大位移；
- 索、预应力、初张力和初应变；
- 接触、间隙、摩擦和滑移；
- 土—结构相互作用；
- 组合效应、徐变收缩、温度和支座位移；
- 施工激活、拆除和体系转换。

未纳入的物理要写明对允许用途的限制。

## 4. 定义作用和阶段

建立作用族清单，不在本节点填入未经核验的数值：自重、附加恒载、活载、人群、设备、施工荷载、风、温度、支座沉降、制动力、离心力、水流、地震、预应力、张拉、架设和临时状态。

对猫道和索系，明确是否需要找形、目标线形、施工温度、人员与设备分布、风环境和抗风体系。

## 5. 建立 standards manifest

每份标准记录：

- `standardId`、编号、名称、版本；
- 颁布机构和 jurisdiction；
- 正式文件 sourceId 与 sha256；
- 生效日期、项目采用日期和替代关系；
- 使用章节和规则类型；
- 是否已由专业负责人批准转换为机器规则。

条文转换结果单独形成 rule pack，保留条文原文定位和人工批准记录。

## 6. 建立响应指标

至少覆盖：

- 位移、转角和净空；
- 支反力、锚固力和基础反力；
- 轴力、剪力、弯矩、扭矩；
- 索力、应力、应变或壳内力；
- 稳定或屈曲指标，若在范围内；
- 质量、重心和固有频率，若用于静力校核或模型验证；
- 施工阶段累计响应。

每个 metric 指定提取位置、坐标系、符号、组合、阈值、容差和复核方法。

## 7. 定义可信度要求

根据结构风险、决策后果和模型新颖程度确定：

- 是否需要第二求解器；
- 是否需要手算或降阶模型；
- 网格收敛层级；
- 高敏感参数情景数；
- 需要的现场、试验或既有模型证据；
- 审批角色和签认顺序。

# 质量门

G0 只有在以下条件满足时通过：

1. modelPurpose、permissibleUse 和 excludedUses 完整；
2. 桥型、阶段、物理范围和输出指标明确；
3. 每个验收标准有数值、单位、来源和适用对象；
4. 标准版本与正式文件哈希已冻结；
5. 初始状态和施工阶段需求已作明确布尔判断；
6. 风险等级与独立复核要求匹配；
7. 专业负责人完成批准。

正式规范文本缺失、用途矛盾或验收标准空缺时，G0=`BLOCKED`。

# 失败处理

若用户只要求“做个静力模型”，先采用受限用途草案：整体结构响应、主要内力和位移，不覆盖局部连接、疲劳、局部屈曲和实体应力。草案仍需用户或专业负责人批准后才能通过 G0。

# 完成检查

1. 每个用途能否对应到具体响应和工程决策？
2. 是否冻结了规范版本与正式文件？
3. 是否区分作用规则、组合规则和抗力规则？
4. 是否明确线性、非线性、初始状态和施工阶段？
5. 是否列出模型无法支持的结论？
6. 是否为控制响应定义位置、符号、单位和阈值？
7. 是否确定独立复核和审批要求？

## 节点 02 · `engineering-source-ingestion`

来源：`skills/02-engineering-source-ingestion/SKILL.md`

---
name: engineering-source-ingestion
description: >
  接收桥梁或猫道项目的 CAD、PDF、图像、表格、设计说明、专项方案、规范和既有模型，建立只读源文件清单、哈希、版本、外部参照、可读性和证据优先级。
  当用户上传资料、补充修订图、替换规范或要求从既有项目恢复计算链时使用。
---

# 任务

你负责建立原始资料的唯一事实入口。目标是确认“有哪些文件、哪个版本有效、文件能否完整打开、外部依赖是否齐全、单位和坐标信息在哪里”，并生成后续所有节点可引用的稳定 sourceId。

# 输入契约

- G0 通过或处于预扫描状态的 analysis charter；
- 用户上传的文件和目录；
- 项目图纸目录、发图单、修订通知和收发记录；
- 已批准的文件格式解析器清单；
- 项目版本优先级规则。

每个文件、外部参照和标准文本生成稳定 sourceRef，后续节点只能通过该引用和内容哈希读取来源。

# 输出工件

- `source_manifest.json`；
- `revision_register.json`；
- `xref_dependency_graph.json`；
- `source_quality_report.json`；
- `duplicate_and_supersession_report.json`；
- 原始文件只读快照与 sha256 清单。

# 不可违反的规则

1. 原始文件只读保存，禁止原位转换或覆盖。
2. 每个文件使用内容哈希识别，文件名只作显示信息。
3. DWG、DGN、IFC、Excel、PDF 等转换文件必须与原文件同时保存并建立 derivedFrom 关系。
4. CAD xref、字体、图片、点云、数据链接和块库缺失要逐项登记。
5. 版本选择依据发图单、修订号、设计说明和项目批准记录；禁止仅按文件时间戳判定。
6. 同一图号多个版本不得静默合并。
7. 密码保护、损坏、字体替换、代理对象、缺失图层和未解析对象全部形成 issue。
8. 规范文本与一般网页摘要分开标识；只有正式文本可进入 standards manifest。
9. 文件中的宏、脚本和外部链接默认不执行。
10. 路径、用户名和临时目录不作为可复现证据；发布包使用 sourceId 和相对路径。

# 工作顺序

## 1. 文件发现

递归列出文件，记录大小、格式、MIME、创建/修改时间、原始路径和上传批次。识别压缩包、嵌套目录和同名文件。

## 2. 哈希与只读快照

计算 sha256。将文件复制到内容寻址目录，设置只读。重复哈希只保留一个物理副本，source manifest 可保留多个逻辑来源。

## 3. 格式与可读性检查

- CAD：版本、model/layout、units、extents、xref、block、proxy object；
- PDF：页数、页面尺寸、是否含向量、字体、嵌入图像和旋转；
- 图像：像素、DPI、颜色空间、方向和压缩；
- 表格：sheet、隐藏行列、合并单元格、公式、外链和名称范围；
- 文档：页数、标题、目录、修订标记和签章页；
- 求解模型：软件、版本、单位、外部库和结果文件依赖。

## 4. 版本链

按图号、文号、标题、修订号和内容相似度生成候选版本链。每条链输出：当前批准版、作废版、待核验版、替代关系和选择证据。

遇到相互矛盾的发图记录时，G1 进入 `BLOCKED`，不自动选取。

## 5. 外部依赖

展开 CAD xref、字体、图片和数据链接。依赖图中任何对几何、文字、尺寸或材料有关键影响的缺失项标记 CRITICAL。

## 6. 单位与坐标预扫描

读取 CAD header、PDF 标题栏、比例标注、坐标网格、里程桩号和已知尺寸。此处只登记声明和候选值，不完成坐标统一。

## 7. 安全与隐私

隔离可能执行的宏和脚本。记录敏感信息位置。对外发布前由节点 18 执行脱敏策略，原始审计包保持受控访问。

# 质量门

G1 检查：

- 每个源文件有 sourceId、sha256、格式、修订和可读状态；

## 节点 03 · `engineering-drawing-data-extraction`

name: engineering-drawing-data-extraction

# 任务

你负责将已冻结源文件转换为“可定位、可验证、未做跨图合并”的图纸实体库。该节点专注忠实提取，不提前决定构件的结构角色和有限元处置。

# 输入契约

- analysis charter；
- source manifest 与当前批准版本；
- xref dependency graph；
- 批准的 CAD/PDF/图像/表格解析器；
- 项目单位与坐标候选；
- OCR 使用阈值和人工复读规则。

每个实体、文字、尺寸和表格单元都必须保存 sourceRef、页/布局定位、解析工具和提取置信度。

# 输出工件

- `drawing_entities.json`；
- `extracted_tables.json`；
- `view_register.json`；
- `dimension_candidates.json`；
- `text_candidates.json`；
- `extraction_coverage_report.json`；
- `extraction_issues.json`；
- 关键证据裁剪图或向量快照。

# 不可违反的规则

1. CAD 原生向量和文字优先于 OCR。
2. PDF 先判断向量页和栅格页；只对栅格区域执行 OCR。
3. OCR 结果必须保存字符级或字段级置信度、像素区域和原图引用。
4. 图纸标注尺寸与几何量测分别存储，禁止在本节点覆盖其中任一项。
5. 未标定比例的图像不得通过像素距离推导工程尺寸。
6. 小数点、负号、直径符号、角度、上下标、钢筋符号和单位必须进行专门校验。
7. CAD 块实例要保存块定义、插入点、比例、旋转和嵌套变换。
8. 实体句柄、layer、linetype、color、layout、viewport 和 xref 来源全部保留。
9. 重复视图、详图和表格行暂不去重，只建立候选关联。
10. 任何解析器丢弃的对象类型要进入 unsupported entity register。

# 工作顺序

## 1. 页面和布局分割

识别 CAD model space、paper space、layout、viewport；识别 PDF 页面尺寸、旋转、标题栏、图框、图号和比例。为每个逻辑图纸分配 SHEET-ID。

## 2. 视图识别

识别平面、立面、纵断面、横断面、节点详图、轴测图、索系线形图、材料表和说明页。每个视图记录 VIEW-ID、页面区域、比例、方向标记和候选坐标轴。

## 3. 几何提取

提取 line、polyline、arc、circle、ellipse、spline、hatch boundary、3D face、mesh、solid、region、point、dimension geometry 和 block instance。保存原始坐标、变换链和几何容差。

对于 PDF 向量，保存 path、stroke、fill、clipping 和 text transform；避免把所有线段提前拼接成轮廓。

## 4. 文字与尺寸

提取文字内容、字体、方向、位置、样式和关联引线。尺寸对象保存：显示文字、测量值、端点、单位、精度、前后缀、公差和 override 状态。

扫描图 OCR 至少进行：

- 方向校正；
- 局部二值化或增强；
- 文字与线框分离；
- 数字字段二次识别；
- 与几何或表格行列结构交叉验证。

关键尺寸若仅有低置信 OCR，标记 CRITICAL 或 MAJOR，不直接进入 accepted dimension。

## 5. 表格提取

保留行列坐标、合并单元格、表头层级、单位行、脚注和跨页关系。材料表、构件表、螺栓表、钢筋表和工程量表分别分类。

每个单元格记录原文、标准化值、单位、置信度和 source locator。

## 6. 覆盖率统计

按图纸页和视图统计：

- 可解析实体数与失败数；
- 文字和尺寸覆盖率；
- 表格单元格覆盖率；
- unsupported 对象；
- OCR 低置信字段；
- 已知尺寸的提取一致性。

## 7. 快照验证

为关键尺寸、材料、构件编号和坐标点生成裁剪图。对 CAD 可生成实体高亮快照。后续节点通过 evidenceId 打开相同区域复核。

# 质量门

G2 通过条件：

1. 所有批准图纸页和布局均已处理；
2. 关键视图、标题栏、图号和修订信息已识别；
3. 关键尺寸和材料字段具有原生提取或经双重校核的 OCR；
4. 已知尺寸的量测比例与声明单位一致；
5. unsupported 对象已评估其工程影响；
6. 提取覆盖率达到 charter 规定阈值；
7. 每个候选值都可定位到源文件和页面/实体区域。

若控制几何只能依赖未标定图像、关键材料字段无法辨认或解析器丢失关键对象，G2=`BLOCKED`。

# 失败处理

同一文件允许使用第二批准解析器复核。两套结果的实体数、extents、文字、尺寸和表格差异要生成对比报告。解析器冲突不能通过简单取平均解决，应在 G2 或 G3 形成问题。

# 完成检查

1. 是否区分原生向量、原生文字和 OCR？
2. 是否保留每个实体的原始 locator 和变换链？
3. 是否保存尺寸显示值与几何测量值？
4. 是否处理块、xref、layout 和 viewport？
5. 是否对表格保留行列与脚注结构？
6. 是否对关键数字执行二次识别和几何校核？
7. 是否统计 unsupported 对象和覆盖率？
8. 是否为关键证据生成可视快照？

## 节点 04 · `bridge-drawing-registration-reconciliation`

# 任务

你负责把节点 03 的独立提取结果连接成跨图证据图，形成每个尺寸、材料、数量、坐标和构造关系的接受值、候选值、冲突和依据。

# 输入契约

- analysis charter 与 standards manifest；
- source manifest、revision register；
- drawing entities、view register、dimension candidates、extracted tables；
- 项目证据优先级；
- 单位和坐标规则；

每个接受事实和冲突处置必须保留参与证据的 sourceRef，并记录跨视图转换和优先级依据。

# 输出工件

- `evidence_graph.json`；
- `coordinate_transform_register.json`；
- `dimension_register.json`；
- `material_register.json`；
- `quantity_register.json`；
- `conflict_register.json`；
- `duplicate_view_and_part_candidates.json`；
- `round_trip_overlay_report.json`。

# 不可违反的规则

1. 冲突值不得取平均，除非项目依据明确要求统计平均。
2. 接受值必须说明证据优先级和覆盖关系。
3. 图纸标注、材料表、设计说明和几何量测保留为独立证据节点。
4. 单位转换前保存原值和原单位。
5. 同一编号的构件不能仅凭编号判定为同一对象；需要位置、几何、材料和装配关系支持。
6. 重复视图去重后仍保留所有来源。
7. 尺寸链必须闭合，闭合误差要与图纸精度和项目容差比较。
8. 视图配准必须保存变换矩阵和残差。
9. 版本优先级可以覆盖旧值，但旧值不能从审计链删除。
10. 高敏感冲突不能在无批准依据时自行选择。

# 工作顺序

## 1. 单位统一

根据 CAD header、标题栏、比例、已知尺寸和项目说明确定每个视图的原单位。将全部 accepted quantity 转换到内部单位制，生成转换审计表。

若单位候选之间存在 10、100、1000 等尺度冲突，使用多个已知尺寸、坐标和标题栏交叉核验，不能只依赖一个实体。

## 2. 坐标配准

建立：

- 全局桥梁坐标；
- 里程或轴线坐标；
- 每张图纸视图坐标；
- CAD 块与 xref 局部坐标；
- 构件局部坐标。

利用轴线、墩号、里程、标高、对称线、控制点和公共几何计算变换。每个变换输出控制点数量、残差和适用范围。

## 3. 跨图关联

使用以下证据组合关联同一对象：

- 构件编号与图号引用；
- 里程、跨号、轴线和标高；
- 截面尺寸和材料；
- 装配父子关系；
- 数量与重复模式；
- 详图索引和剖切符号。

关联结果可分 `CONFIRMED`、`PROBABLE_WITH_BOUNDS`、`CONFLICT`。`PROBABLE_WITH_BOUNDS` 必须进入假定登记。

## 4. 尺寸协调

建立尺寸链和派生尺寸：总长、分段长、中心距、板厚、孔距、标高差、索长、垂度和截面尺寸。比较：

- 标注尺寸之间；
- 标注与表格；
- 标注与坐标；
- 标注与几何量测；
- 新旧版本。

决定 accepted value 时使用项目证据优先级，记录 rejected candidates 和理由。

## 5. 材料与数量协调

统一材料牌号、强度等级、密度、弹性模量来源、构件数量和重量。材料别名映射要保留原文。表中总重与分项重量进行对账。

## 6. 构建证据图

证据图至少有以下关系：

- `supports`：证据支持工程事实；
- `contradicts`：证据冲突；
- `supersedes`：新版本覆盖旧版本；
- `derived_from`：计算值来源；
- `depicts`：视图描绘对象；
- `references`：详图或说明引用；
- `located_at`：对象位置；
- `part_of`：装配父子关系。

## 7. 回投验证

把 accepted coordinates、轮廓和构件编号回投到原图视图，生成 overlay。检查控制点、轮廓、标高和尺寸是否对齐。配准错误不能留到几何建模节点处理。

# 质量门

G3 通过条件：

1. 所有关键视图具有已验证的单位和坐标变换；
2. 控制尺寸、材料、数量和标高存在唯一 accepted value 或已批准参数边界；
3. 没有未关闭的 CRITICAL 冲突；
4. 尺寸链闭合误差在项目阈值内；
5. 版本覆盖关系明确；
6. 每个 accepted value 可回溯到一个或多个证据节点；
7. 回投 overlay 在关键控制点满足容差；
8. 高敏感有界值已建立 assumptionId。

# 失败处理

若详图与总图冲突，按项目计算原则、发图记录和修订关系确定优先级。无法确定时，保留多个工程情景并判断其对控制响应的影响；若合理情景会改变模型拓扑、荷载路径或验收结论，G3=`BLOCKED`。

# 完成检查

1. 是否为每个视图确定单位和坐标变换？
2. 是否保存变换残差和控制点？
3. 是否避免对冲突值取平均？
4. 是否建立尺寸链、材料表和数量对账？
5. 是否保留 accepted、rejected 和 superseded 值？
6. 是否建立完整证据关系？
7. 是否执行回投 overlay？
8. 高敏感冲突是否被参数化或阻断？

## 节点 05 · `bridge-structural-semantic-inventory`

---
name: bridge-structural-semantic-inventory
description: >
  将已协调的桥梁或猫道图纸事实组织为工程构件组、制造零件映射、结构角色、装配关系和主要传力路径图。

---

# 任务

你负责建立有限元抽象之前的工程语义清单。此节点回答“图纸中有哪些工程对象、它们属于哪个系统、如何连接、承担什么结构作用、荷载如何传递”，暂不决定显式建模或等效处置。

# 输入契约

- analysis charter；
- evidence graph、dimension/material/quantity register；
- bridge family 与施工阶段；
- 图纸中的构件编号、装配层级和材料表；
- 项目构件分类词典和桥型本体。

# 输出工件

- `component_inventory.json`；
- `part_component_map.json`；
- `assembly_graph.json`；
- `load_path_graph.json`；
- `annotation_and_nonpart_register.json`；
- `orphan_evidence_audit.json`；
- `semantic_issues.json`。

# 不可违反的规则

1. 工程构件组与制造 Part 分开管理。
2. 每个制造 Part 必须归入且只归入一个工程构件组，或明确标记为注释、尺寸、图框、工艺信息或重复表达。
3. 同一 Part 在平面、立面、剖面、详图和材料表出现多次只计一个逻辑对象。
4. 结构角色依据装配、位置、连接和传力证据，不依赖图层名称或绘图颜色。
5. 此节点禁止提前给出有限元单元类型和四类处置。
6. 连接件只有在具备独立相对运动、间隙、滑移、接触、初始力或独立荷载路径时，才建立独立工程对象候选。
7. 附属设施也要进入清单，因为它们可能贡献质量、荷载或迎风面积。
8. 临时结构和施工阶段构件不能因最终成桥不存在而删除。
9. 语义置信度与工程关键性分别记录。
10. 任何无法放入装配关系或传力路径的对象进入 orphan audit。

# 工作顺序

## 1. 确定系统层级

按项目建立系统树，例如：

- 上部结构；
- 下部结构与基础；
- 支承和伸缩体系；
- 缆索、吊索、锚固和索鞍；
- 横向和抗风体系；
- 桥面系和附属设施；
- 猫道、支架、门架和施工临时结构；
- 监测、检修和设备系统。

## 2. 识别工程构件组

对每组记录：

- componentGroupId 和名称；
- bridge family 与系统；
- 空间范围和重复规则；
- source Part；
- 材料和截面候选；
- 父装配与子对象；
- 结构角色；
- 可能参与的物理通道；
- 施工阶段存在性；
- sourceRefs 和 assumptionRefs。

## 3. 制造零件归并

归并依据包括：共同形成同一截面、共同组成节点、焊接或螺栓固定、无独立相对运动、在材料表中属于同一装配、重复小件承担分布作用。

若零件之间存在可观相对滑移、转动、张拉、接触或独立受力，保留独立对象并记录关系。

## 4. 建立装配图

使用 `part_of`、`connected_to`、`supported_by`、`anchored_to`、`suspended_from`、`braced_by`、`acts_on` 等关系表达装配和受力联系。

连接关系要指明位置、方向、连接对象、证据和是否随施工阶段改变。

## 5. 建立主要传力路径

至少建立：

- 竖向荷载路径；
- 横向与扭转载荷路径；
- 纵向力路径；
- 索力、拱推力或预应力路径；
- 支承、锚固和基础路径；
- 风荷载与质量作用路径；
- 猫道人员、设备和风作用到锚固端的路径。

图中每条边记录传力类型、方向、阶段和证据。检查是否存在断链、孤立系统和未解释旁路。

## 6. Part 覆盖审计

对材料表、构件表和图纸标注中的每个 Part 编号逐一映射。重复编号要按位置或实例区分。无法映射的 Part 进入 orphan audit，禁止直接丢弃。

## 7. 语义一致性

检查：

- 名称与装配位置；
- 数量与重复模式；
- 材料与截面；
- 父子关系；
- 支承和锚固方向；
- 施工阶段存在性；
- 图纸详图索引。

# 质量门

G4 通过条件：

1. 所有制造 Part 已唯一映射或分类为非 Part；
2. 所有工程构件组有结构角色、空间位置和来源；
3. 主要传力路径从作用点连续到支承、锚固或基础；
4. 支承、连接、索系和临时结构没有孤立对象；
5. 装配数量与材料表对账；
6. CRITICAL orphan 为零；
7. 高关键低置信对象已建立假定或阻断；
8. 节点 06 可以直接读取 component inventory 作抽象决策。

# 失败处理

若某零件无法识别具体名称，但可根据装配和位置确认属于父构件，则以中性名称归入该父构件，并保留原 Part 编号和 assumptionId。若该零件可能形成独立传力路径或边界，G4 进入 `BLOCKED`，直到通过详图、说明或有界情景解决。

# 完成检查

1. 每个 Part 是否只出现一次逻辑映射？
2. 是否区分工程构件组、制造零件和图纸注释？
3. 是否建立完整装配图和传力路径图？
4. 是否记录施工阶段存在性？
5. 是否覆盖附属设施和临时结构？
6. 是否识别连接处的独立相对行为？
7. 是否完成数量与材料表对账？
8. 是否清零 CRITICAL orphan？

## 节点 06 · `bridge-cad-fem-abstraction`

来源：`skills/06-bridge-cad-fem-abstraction/SKILL.md`

---
name: bridge-cad-fem-abstraction
description: >
  将已完成证据协调和工程构件归并的桥梁、猫道或施工临时结构，转化为面向指定分析目标的有限元工程抽象决策。
  当任务需要为每个工程构件组唯一选择显式建模、等效计入、仅计质量/荷载或不纳入，并规定刚度、质量、连接、边界、初始状态和验证目标时使用。
  不用于原始 OCR、逐件抄录材料表、无分析目标的几何复刻，也不承担最终设计签认。
---

# 任务

你负责作出桥梁有限元工程抽象决策。目标聚焦受力路径、控制响应和物理完整性，不做制造几何的无差别复刻。

先确定结构如何传力，再决定工程构件组如何表达。不得先把所有零件显式建模，再凭复杂度删减。

# 输入契约

必须读取：

- `analysis_charter`：模型用途、结构阶段、分析类型、控制响应、允许用途和排除用途；
- `component_inventory`：工程构件组、制造 Part、结构角色、装配关系；
- `load_path_graph`：竖向、横向、纵向、扭转、索力、锚固和基础传力路径；
- `evidence_graph`：尺寸、材料、数量、连接、支承和版本证据；
- `assumption_register`：已批准参数边界；
- `standards_manifest`：项目正式规范和规则包；
- 求解器能力矩阵，仅用于判断表达可实现性，不得以软件限制改写物理目标。

上游 G4 未通过时不得执行正式抽象。

# 输出工件

- `abstraction_decisions.json`；
- `abstraction_validation_plan.json`；
- `part_to_component_to_representation_map.json`；
- `excluded_component_audit.json`；
- `mass_and_load_duplication_risk.json`；
- `high_sensitivity_abstraction_scenarios.json`。

# 默认分析范围

若 charter 只给出整体静力复核，采用以下受限范围：

“建立图纸所示阶段的整体结构响应模型，关注主要传力路径、整体刚度、内力、变形、质量分布、支承约束和初始力；局部螺栓、焊缝、孔壁承压、接触滑移、局部屈曲、疲劳热点和实体细节另设专项模型。”

施工阶段、几何非线性、风致响应、地震、局部应力、疲劳、稳定或连接滑移等用途由 charter 覆盖默认范围。

# 决策封闭性

每个工程构件组必须且只能选择一种处置：

- `显式建模`
- `等效计入`
- `仅计质量/荷载`
- `不纳入`

处置本身不得留空，也不得增加第五类占位状态。缺失事实要形成 assumption，并给出确定的参数化表达或情景。

质量门可以阻断发布：若高敏感参数的有依据范围导致控制响应跨越验收限值，G5=`BLOCKED`，同时保留已经作出的处置和所需补充信息。

# 决策对象

决策对象是工程构件组。制造 Part 已在节点 05 完成归并。

- 多块钢板、加劲肋、角钢、螺栓和焊缝共同形成梁、箱室、节点或连接时，优先作为父构件的组成部分。
- 重复视图、剖面、详图和材料表中的同一零件只计一次。
- 相对滑移、转动、间隙、接触、初始力、局部变形或独立荷载路径影响控制响应时，连接对象可以独立表达。
- 一个构件组可保留多个物理通道，但处置只能有一个。

# 证据优先级

按以下顺序采用依据，前项可以覆盖后项：

1. 项目计算原则、经审查模型、设计说明和专项施工方案；
2. 当前批准图纸中的尺寸、材料、剖面、详图、总装关系和跨图一致证据；
3. standards manifest 中已批准的规范规则；
4. 对应桥型和分析目标的成熟工程建模惯例；
5. 保留控制响应相关物理效应的参数化默认表达。

不得仅依赖构件尺寸大小、图层名、颜色、绘图精细程度或出现次数。

# 处置规则

## 显式建模

满足任一条件时选择：

- 定义主要传力路径或结构拓扑；
- 几何连续性、偏心、曲率、垂度或空间位置直接控制目标响应；
- 需要单独提取内力、位移、索力、应力、稳定或阶段响应；
- 决定支承、锚固、接触、滑移、约束或初始状态；
- 几何非线性、材料非线性、施工阶段或局部分析要求保留其独立行为；
- 低阶等效无法同时保留所需刚度、质量、边界和初始力。

必须给出 element family、参考线/面、自由度、局部坐标、连接接口、阶段存在性和输出请求。

## 等效计入

构件作用不可忽略，局部制造几何不进入控制响应时选择。必须指定等效对象、参数、保留效应、舍弃细节和验证项目。

允许表达包括：

- 等效面积、惯性矩、扭转常数、翘曲常数或剪切面积；
- 轴向、弯曲、扭转和剪切刚度；
- 平动、转动、滑移、间隙或接触刚度；
- 刚臂、偏心、MPC、耦合和约束关系；
- 等效膜、壳、梁格或分布连接；
- 初张力、初应变、预应力和施工初始状态；
- 质量与转动惯量，且通过 ledger 防止与自重重复。

## 仅计质量/荷载

构件不形成独立刚度、边界或传力路径，但以下作用需要保留时选择：

- 自重或附加恒载；
- 集中质量、分布质量或转动惯量；
- 人员、设备、施工、检修和堆载；
- 迎风面积、阻力或气动附加作用；
- 温度、附属设施或铺装形成的等效作用。

必须指定施加到哪个父构件、节点、线或面，说明分配规则和重复计入检查。

## 不纳入

仅当该构件在 charter 范围内不承担目标相关传力、刚度、质量、荷载、边界、初始状态或气动作用，或其作用已完整进入父构件时选择。

排除理由必须指出影响通道为何不进入控制响应，或已经在哪个等效项中计入。禁止以尺寸小、数量多或建模困难作为理由。

# 工作顺序

## 1. 固定用途与结构阶段

从 charter 提取 bridgeFamily、analysisTypes、stages、controlMetrics、excludedUses 和 riskClass。对每个 useCaseId 单独判断抽象要求；多个用途冲突时选择能覆盖全部用途的表达，或拆成不同模型分支。

## 2. 检查传力路径

逐条读取 load-path graph，确认作用点到基础或锚固端的路径。标出：

- 拓扑关键构件；
- 支承、约束和锚固；
- 偏心和刚臂；
- 索、拱、预应力和初始力；
- 横向与抗扭体系；
- 质量和风作用传递；
- 施工阶段激活、拆除和体系转换。

任何简化都不得使路径断裂。

## 3. 识别影响通道

每个构件组从以下通道选择：

`传力`、`刚度`、`质量`、`荷载`、`边界`、`初始状态`、`气动`、`局部响应`。

对每个通道写明影响的 metricId 和阶段。

## 4. 生成候选表达

至少比较一个显式方案和一个低阶方案，除非结构拓扑强制显式。比较维度包括：

- 对目标响应的物理完整性；
- 参数可获得性；
- 求解器支持；
- 网格和收敛成本；
- 可验证性；
- 变更维护成本；
- 局部结果误用风险。

最终只保留一个处置，并记录未选方案及理由。

## 5. 定义 representation contract

对显式或等效对象至少定义：

- 几何参考：中心线、中面、实体边界、目标线形；
- element family 候选及必要自由度；
- 材料和截面接口；
- 连接和边界接口；
- 偏心、局部坐标和 orientation；
- 初始状态和阶段；
- 质量与荷载归属；
- 输出位置和结果解释；
- 求解器不支持时的处理原则。

## 6. 处理缺失信息

- 连接刚度未知且影响响应：采用参数化平动/转动弹簧，建立低、中、高情景；
- 摩擦、滑移或间隙未知：保留可滑移或接触表达，明确边界；
- 索初张力未知：保留索单元和初始状态参数，通过目标线形、项目控制值或参数包络确定；
- 附件质量未知：由可读几何、材料、数量或批准附加恒载形成 quantity ledger；
- 影响方向不唯一：依据坐标和装配关系定义方向，并建立方向情景；
- 局部零件作用无法与父构件分离：并入父构件，不单独显式。

## 7. 桥型先验

### 梁桥、箱梁桥和钢—混组合桥

- 主梁、桥面板、主要横梁/横隔梁、支座、桥墩和控制整体受力的连接按目标显式建模。
- 纵横向加劲肋、局部补强板和重复小板在整体分析中并入等效截面或壳刚度；局部屈曲、疲劳和热点分析时显式。
- 剪力钉、螺栓、焊缝和连接板在整体分析中等效为组合连接、刚臂、MPC 或弹簧；滑移、局部承压或疲劳为目标时显式。
- 普通钢筋在整体模型中并入截面或材料；开裂、钢筋应力和局部破坏为目标时采用分层或显式表达。
- 预应力束在施工阶段、损失、线形和二次效应为目标时保留束线和初始作用；受限运营阶段模型可等效为初始力、初应变或截面作用。
- 铺装、护栏、管线和附属设施默认计质量/荷载；有经批准复合作用依据时才计刚度。

### 拱桥和桁架桥

- 拱肋、系杆、主桁弦杆、腹杆、吊杆、横撑和稳定体系显式。
- 节点板、拼接板、螺栓和焊缝在整体分析中等效连接刚度、偏心和节点域；局部应力、疲劳、滑移或屈曲为目标时显式。

### 斜拉桥和悬索桥

- 主梁、桥塔、斜拉索、主缆、吊索、锚碇、控制体系的索鞍与支承显式。
- 索体系保留线形、轴向刚度、自重、垂度、初张力/初应变、连续性和几何非线性。
- 索夹、锚具局部板件、螺栓和焊缝在整体分析中等效连接、偏心、刚度或质量；局部锚固、疲劳、滑移或接触为目标时显式。
- 护栏、检修道、管线和附属设备计质量/荷载；风分析还要保留迎风面积或气动参数。

### 下部结构与基础

- 桥墩、桥台、盖梁、桩基、承台和支座按整体或局部用途显式。
- 土体和地基在整体模型中采用参数化弹簧、阻抗或经验证等效边界；局部土—结构相互作用为目标时采用连续介质。
- 垫石、灌浆层和局部配筋在整体分析中并入支承或截面；局部承压、开裂或损伤为目标时显式。

### 猫道、支架和临时结构

- 承重索、门架承重索、门架、横梁、主要抗风构件、锚固端、转索鞍和控制体系响应的支承显式。
- 面网、扶手网、栏杆索、踏板和重复连接件按用途等效刚度、质量、荷载或迎风面积。
- 小型夹具、连接板、销轴和螺栓组在整体模型中等效连接、刚臂、MPC、弹簧或集中质量；局部连接行为为目标时显式。

## 8. 定义验证目标

每项抽象至少配置一项验证：

- 总质量、重心、截面面积和惯性；
- 简化模型与精细子模型刚度；
- 静力挠度、支反力和关键内力；
- 前若干阶频率和振型；
- 连接单位荷载刚度；
- 目标线形、索力和初始平衡；
- 对称性、极限情形和参数敏感性。

验证阈值来自 charter，不得在本节点临时设定宽松容差。

# 输出格式

每个 decision 至少包含：

- `componentGroupId`
- `componentName`
- `sourceParts`
- `bridgeFamily`
- `useCaseIds`
- `structuralRole`
- `loadPathPosition`
- `effectChannels`
- `metricIds`
- `disposition`
- `representation`
- `equivalentParameters`
- `sourceRefs`
- `assumptionRefs`
- `decisionBasis`
- `discardedDetails`
- `sensitivityClass`
- `parameterScenarios`
- `validationChecks`
- `downstreamInterfaces`
- `misuseWarning`

处置理由使用明确句式：

“该工程构件组通过【物理效应】影响【目标响应】，因此选择【唯一处置】；采用【有限元表达】保留【必须保留的效应】，舍弃【不进入目标响应的局部细节】，并通过【验证项目】检查表达是否成立。”

# 质量门

G5 通过条件：

1. 每个 componentGroupId 只有一种处置；
2. 所有制造 Part 可追溯到构件组和 representation；
3. 主要传力路径、支承、锚固、初始力和控制几何连续；
4. 每个等效项有参数、来源、保留效应、舍弃细节和验证；
5. 质量、自重、附加恒载和迎风面积无重复归属；
6. 不纳入项有目标响应层面的排除理由；
7. 高敏感缺失信息已参数化；
8. representation contract 足以驱动节点 07 至 11；
9. 求解器不支持项已阻断或有批准等效；
10. 专业负责人批准抽象工件哈希。

若参数包络跨越验收限值、关键路径缺失或表达无法验证，G5=`BLOCKED`。

# 失败处理

若多个用途要求冲突，例如整体模型需要等效加劲肋，局部屈曲模型需要显式加劲肋，建立两个 model branch，共享 evidence graph 和 component inventory，分别输出 abstraction decisions。禁止把两种用途混成一个含义不清的模型。

# 完成检查

1. 是否基于用途和传力路径，而非图纸细节数量作决策？
2. 每个构件组是否只有一种处置？
3. 是否保留边界、偏心、初始状态和阶段效应？
4. 每个等效项是否可由确定性参数生成？
5. 质量和荷载是否有唯一 ledger 归属？
6. 排除项是否有可审计理由？
7. 高敏感假定是否形成情景与 gate 判定？
8. 下游接口是否完整？
9. 验证项目是否绑定 charter metric 和阈值？
10. 是否列出模型误用警告？

# 任务

你负责生成有限元几何与拓扑中间表示。输出必须保留设计几何、分析参考几何和两者之间的偏移关系，使节点 08 至 14 能在不重新解释图纸的条件下继续工作。

# 输入契约

- analysis charter；
- evidence graph、coordinate transform register；
- abstraction decisions 与 representation contract；
- dimension register；
- project tolerance policy；
- solver-neutral element capability model。

# 输出工件

- `fem_geometry_ir.json`；
- `topology_audit.json`；
- `geometry_overlay_report.json`；
- `coordinate_system_register.json`；
- `geometry_parameter_table.json`；
- `node_merge_log.json`；
- `geometry_issues.json`。

# 不可违反的规则

1. 设计几何与分析参考几何分开保存。
2. 所有坐标带 coordinateSystemId 和单位。
3. 节点合并只按项目容差和拓扑语义执行，禁止依赖求解器自动合并。
4. 交叉线若存在结构连接必须生成共享节点或连接对象；仅投影交叉时禁止误连。
5. 梁、索、壳的局部轴和 orientation 显式定义。
6. 偏心、刚臂和参考面 offset 不能通过移动几何后丢失物理来源。
7. 曲线离散误差要绑定 chord error、角度或响应敏感性。
8. 零长度、重复单元、悬空节点、自交面和负体积禁止进入下游。
9. 对称复制、阵列和镜像要保存生成规则和实例 ID。
10. 所有几何对象必须回溯到 componentGroupId、sourceRefs 和 abstraction decision。

# 工作顺序

## 1. 建立坐标系统

冻结全局桥轴坐标。为斜交桥、曲线桥、塔柱、索面、横梁、支座和局部节点建立局部坐标系。记录原点、轴向、右手性和父坐标系。

## 2. 生成参数骨架

按工程角色建立：

- 梁、桁架、索和杆件中心线；
- 壳中面和板件参考面；
- 实体分析域；
- 支承、锚固、连接和荷载作用点；
- 桥轴、里程、跨界和阶段控制点。

所有关键节点优先由标注尺寸、坐标和装配关系计算，避免从绘图线长度直接量取。

## 3. 处理偏心与参考位置

记录构件真实形心、剪心、连接面、中面和分析线之间的偏移。决定采用：

- 节点坐标偏移；
- element offset；
- 刚臂；
- MPC；
- 壳厚偏置；
- 独立连接节点。

选择必须遵循 abstraction contract，并保留偏心向量来源。

## 4. 拓扑连接

对每个连接位置判断：共节点、端部释放、MPC、刚臂、弹簧、接触或无连接。节点 07 只生成几何接口，具体刚度和自由度由节点 09 定义。

执行图论检查：连通分量、度数异常、孤立节点、意外闭环和路径断点。

## 5. 曲线和索线离散

- 曲梁按曲率、截面变化、荷载变化和目标响应分段；
- 索按初始曲线、垂度、集中连接和找形要求分段；
- 壳面按边界、开孔、加劲、支承和局部输出区分区；
- 实体域按接触、材料和应力梯度分区。

本节点生成几何分段，网格密度最终由节点 12 决定。

## 6. 节点合并

合并候选要同时满足：

- 空间距离小于 merge tolerance；
- 所属结构接口允许共节点；
- 坐标系和阶段兼容；
- 不存在间隙、滑移、接触或偏心要求。

每次合并记录 old IDs、new ID、距离和依据。禁止批量合并后丢失记录。

## 7. 几何不变量检查

至少检查：

- 跨径、总长、标高和关键间距；
- 截面站点和构件端点；
- 支座、锚固和索鞍坐标；
- 对称关系；
- 构件交点；
- 闭合轮廓和壳法向；
- 设计线形与分析线形差异。

## 8. 回投图纸

把 FEM 参考线、中面、节点和偏心矢量回投到对应视图。生成平面、立面、横断面和节点详图 overlay。对每个控制点输出偏差。

# 质量门

G6 通过条件：

1. 所有显式和等效构件有稳定几何接口；
2. 全局和局部坐标系闭合且右手性正确；
3. 关键尺寸、坐标和标高在项目容差内；
4. 无零长度、重复、孤立、误连、自交或负体积对象；
5. 偏心和 offset 全部显式；
6. 节点合并日志完整；
7. 传力路径在拓扑图中连续；
8. 回投 overlay 通过；
9. 高敏感几何参数以情景或参数表表达。

# 失败处理

若图纸只能确定端点而无法确定曲线中间线形，使用 abstraction decision 中批准的参数曲线或找形分支，并将几何状态标记为 `requiresInitialState=true`。若未知线形会改变连接位置、净空或验收结论，G6=`BLOCKED`。

# 完成检查

1. 是否分开保存设计几何和分析参考几何？
2. 是否显式记录坐标系、偏心和局部轴？
3. 是否区分真实连接与投影交叉？
4. 是否记录每次节点合并？
5. 是否检查拓扑连通和孤立对象？
6. 是否按曲率和结构断点分段？
7. 是否执行关键尺寸不变量检查？
8. 是否完成图纸回投？

- 形心、剪心；
- 线质量和表面积；
- 组合截面换算属性；
- 壳厚和层合信息；

- 手工公式；
- 第二几何积分库；
- CAD region 属性；
- 材料表总重反算；
- 标准型钢表。

比较差异并使用 charter 阈值判断。

## 6. 分配属性

将 MAT-ID、SEC-ID 和 mass item 映射到 geometry object 和 componentGroupId。检查 orientation 与局部轴一致，截面变化站点与图纸一致。

# 质量门

G7 通过条件：

1. 所有需要刚度的对象有材料和截面；
2. 所有质量/荷载对象有唯一 ledger 归属；

# 工作顺序

## 1. 建立接口清单

从 assembly graph 和 load-path graph 列出所有：

- 构件端部连接；
- 梁—塔、梁—墩、梁—支座；
- 索—锚具、索—索鞍、吊索—主缆/主梁；

- fixed；
- released；
- linear spring；
- nonlinear spring；
- gap/contact；
- friction/slip；
- coupled/MPC；
- prescribed displacement；
- stage-dependent。

记录力和位移正方向。

- 重复约束检查；
- 约束方程线性相关检查；
- 刚体自由度检查；
- 意外机制检查；
- 封闭刚性环和数值病态风险；

- 对称模型边界检查。

为关键连接设计单位平动、单位转动或单位索力测试。预期输出包括力流、相对位移、转角、反力方向和等效刚度。

G8A 通过条件：

# 任务

你负责生成满足目标几何和静力平衡的初始状态，并证明该状态能作为后续荷载分析的零时刻。对不需要初始状态的普通线性结构，输出 `NOT_APPLICABLE` 及判定依据。

# 输入契约

- analysis charter 中的 `requiresInitialState`；
- FEM geometry IR；
- material and section libraries；
- connection IR 与 boundary IR；
- 目标线形、目标垂度、目标索力或张拉控制值；
- 自重、施工温度、张拉顺序和阶段信息；
- 锚固、鞍座、摩擦、滑移和锁定规则；
- assumption scenarios。

每个目标线形、张力、温度、无应力长度和锁定事件都要绑定 sourceRef 或 assumptionRef。

# 输出工件

- `initial_state_ir.json`；
- `form_finding_report.json`；
- `initial_state_scenarios.json`；
- `target_geometry_comparison.json`；
- `initial_equilibrium_audit.json`；
- `prestress_and_lock_in_ledger.json`；
- `initial_state_issues.json`。

# 不可违反的规则

1. 索单元默认只承受拉力，任何压缩状态要形成错误或专门物理说明。
2. 几何非线性和大位移在找形阶段显式开启。
3. 自重是否参与找形必须明确，且与后续荷载阶段防止重复。
4. 目标几何、目标垂度和目标索力不能无约束地同时指定；应选择独立控制量并记录剩余量作为结果。
5. 初张力、初应变、无应力长度和目标线形之间的转换公式与程序版本必须记录。
6. 施工温度、材料温度系数和安装温度不可省略。
7. 鞍座滑移、摩擦、索连续性和锚固条件按实际体系表达。
8. 找形收敛需同时满足力残差和几何误差，不能只看求解器“完成”。
9. 初始状态必须在无新增外荷载下保持平衡。
10. 多场景初始状态各自独立保存，不得覆盖名义状态。

# 工作顺序

## 1. 选择初始状态类型

按对象选择：

- 索系找形：目标坐标、垂度或索力；
- 斜拉索调索：目标主梁线形、索力或塔偏；
- 猫道找形：承重索线形、门架和横梁位置、抗风索状态；
- 预应力：束线、张拉力、摩阻、锚具回缩和阶段损失；
- 施工锁定：临时支承拆除、体系转换、顶推或合龙形成的内力；
- 拱或柔性结构：目标几何下的自平衡状态。

## 2. 定义独立控制量

每个索段或预应力对象明确：

- 已知端点和高差；
- 已知无应力长度、初应变、张拉力、水平分力、垂度或中间控制点中的独立集合；
- 自重和附加恒载；
- 温度；
- 鞍座连续、滑移或摩擦；
- 施工阶段激活顺序。

检查约束数量，避免欠定或超定的目标输入。

## 3. 初始解析估算

在进入非线性求解前，使用悬链线、抛物线近似、索单元解析式或预应力损失公式形成初值。初值只用于收敛，不作为最终结果。

## 4. 非线性找形

按批准算法执行力密度、目标力迭代、无应力长度迭代、逆分析或阶段迭代。每次迭代记录：

- 几何误差范数；
- 不平衡力范数；
- 最小/最大索力；
- 锚固和鞍座反力；
- 迭代参数；
- 收敛原因。

## 5. 猫道专项

猫道模型至少检查：

- 承重索、门架承重索、横梁和门架的自重线形；
- 面网、踏板、扶手网和栏杆索的质量/荷载归属；
- 抗风索、横向联系和锚固的初始张力；
- 工作面高程、宽度、坡度和净空；
- 人员、设备和局部堆载作用前的基础状态；
- 施工温度和风环境情景；
- 锚固端、转索鞍和塔顶门架反力。

## 6. 预应力和施工锁定

区分张拉控制力、有效预应力、初始应变、等效荷载和阶段损失。若求解器使用等效荷载，仍要在 ledger 中保留物理束线和张拉来源，防止与初始应变重复。

## 7. 初始平衡复核

移除所有后续活载和临时扰动，仅保留定义初始状态所需作用。检查：

- 全局和局部反力平衡；
- 目标点坐标误差；
- 索力为正且在合理范围；
- 塔、梁、门架和锚固初始位移；
- 无异常机制或接触穿透；
- 切线刚度可用于后续阶段。

## 8. 参数情景

对初张力、摩擦、滑移、温度、索面积和连接刚度等高敏感参数建立 low/nominal/high 或项目批准分布。每个情景输出独立 ISTATE-ID。

# 质量门

G8B 通过条件：

1. 初始状态类型和控制量定义完整；
2. 找形算法、初值和收敛阈值已冻结；
3. 力残差和几何误差均满足 charter；
4. 索无非物理压缩，锚固反力平衡；
5. 自重、预应力和等效荷载无重复；
6. 施工温度和阶段锁定已考虑；
7. 名义与边界情景均可收敛；
8. 初始状态在无新增外荷载下稳定；
9. 初始状态可被求解器适配器完整映射。

# 失败处理

若目标线形、索力和无应力长度相互矛盾，生成目标冲突报告，指出最小不可满足集合。禁止通过放宽全部收敛阈值获得表面成功。若只有部分情景收敛或索出现松弛导致体系改变，G8B=`BLOCKED`。

# 完成检查

1. 是否明确控制量和从属结果？
2. 是否开启几何非线性和拉力单向？
3. 自重是否在找形与后续阶段只计一次？
4. 是否处理温度、鞍座、摩擦和锚固？
5. 是否同时检查几何误差和力残差？
6. 是否验证所有索力为正或按松弛物理处理？
7. 是否建立名义和边界情景？
8. 是否输出可重放的初始状态参数？

# 工作顺序

## 1. 单元选择

- truss/cable：仅轴向、拉力单向、初始应变；
- beam/frame：轴向、弯曲、扭转、剪切、翘曲；
- shell：膜、板弯曲、横向剪切、厚度积分；
- solid：局部三维应力、接触和复杂几何；
- spring/connector：平动、转动、间隙、摩擦和耦合；
- rigid/MPC：几何约束和荷载分配。

每个选择说明保留物理、舍弃自由度和适用范围。

## 2. 网格分区

在以下位置设置强制节点或网格边界：

- 支承、连接、集中荷载和输出点；

- 曲率和折线变化；
- 开孔、节点域和局部加劲；
- 接触边界；
- 施工阶段激活边界；
- 索夹、门架、横梁和索鞍连接点。

## 3. 网格质量

- 梁/索长度与截面尺度比；
- 曲线 chord error；
- 壳 aspect ratio、warpage、skew、Jacobian 和法向一致性；
- 实体 aspect ratio、Jacobian、负体积和过渡率；
- 弹簧零长度与局部轴；
- 刚臂长度和病态刚度风险。

## 4. 收敛层级

对每个关键 metric 至少定义 coarse、baseline、fine 三层，或给出经批准的等效误差估计方案。每层记录：

- 网格参数；
- 元素和自由度数量；
- 预期计算成本；
- 比较位置和结果；
- 相对/绝对差阈值；
- 单调性或振荡处理。

整体梁桥可对关键构件分段细化；壳/实体模型需关注局部峰值的路径依赖，使用截面合力或热点外推等稳定量作收敛指标。

## 5. 非线性控制

定义：

- load/displacement control；
- 增量初值、最小值、最大值；
- Newton、modified Newton、arc-length 或其他批准算法；
- 力、位移、能量残差阈值；
- 线搜索；
- 接触和摩擦迭代；
- 几何刚度和大位移；
- 允许的 cutback 序列；
- 终止条件。

数值控制变化只允许在节点 14 的批准重试序列中发生。

## 6. 输出请求

只请求能支持 charter metrics 和验证的结果：节点位移、反力、构件内力、壳合力、应力、索力、连接相对位移、能量、残差、接触状态和阶段历史。

输出位置、坐标系、截面站点和平均/外推方式明确。

## 7. 组装 FEM-IR

将 geometry、materials、sections、connections、BC、initial states、loads、combinations、stages、elements、mesh 和 outputs 合并到统一 schema。执行 ID 唯一性和引用完整性检查。

# 质量门

G10 通过条件：

1. 每个模型对象有兼容的单元族和自由度；
2. 网格边界覆盖所有结构与荷载不连续点；
3. baseline 网格满足质量阈值；
4. control metrics 有预先定义的收敛计划；
5. 非线性控制与物理问题匹配；
6. 求解器所需特性均在 capability matrix 中受支持；
7. 输出请求足以完成 G13 至 G15；
8. FEM-IR schema、ID 和引用完整；
9. 数值稳定措施不会改变目标静力物理；
10. 高风险模型的粗、基准、细网格可以自动生成。

# 失败处理

若求解器缺少某项关键单元或非线性功能，输出 feature gap。只有在节点 06 已批准等效表达、节点 17 有独立验证计划时才能继续；其余情况 G10=`BLOCKED`。

# 完成检查

3. 是否定义单元质量阈值？

5. 非线性残差和步长是否在求解前冻结？

2. schema 通过只代表格式正确，仍需物理检查。
3. 求解器警告不能替代本节点检查。
4. 单位、坐标和符号错误按 CRITICAL 处理。
5. 任何未引用 material、section、node、element、load 或 stage 都要登记。
6. 模型中不允许存在未解释的孤立连通分量。
7. 荷载总量和质量总量要与上游 ledger 对账。
8. 约束应允许预期刚体模态数量，且不产生额外机制。
9. 简单单位测试失败时禁止正式求解。
10. 预求解检查脚本版本和阈值必须固定。

# 工作顺序

## 1. 数据契约检查

验证：

- envelope 和 FEM-IR schema；
- ID 唯一性；
- 所有引用存在；
- 单位可解析；
- 坐标系存在且无循环；
- stage 和 combination 引用合法；
- sourceRefs/assumptionRefs 覆盖。

## 2. 数量级与单位

统计结构 extents、最小/最大构件长度、截面尺寸、材料模量、密度、弹簧刚度、荷载和初张力。与项目合理范围、图纸和 ledger 对比。

重点查找：mm/m、N/kN、kg/t、Pa/MPa、角度 deg/rad、密度/重度混淆。

## 3. 拓扑与连通

检查：

- 连通分量；
- 孤立节点和元素；
- 重复节点/元素；
- 跨越但未连接；
- 非预期刚性短路；
- load-path graph 到 FEM graph 的映射；
- 支承、锚固和基础路径。

## 4. 属性覆盖

确保每个元素有 material、section/thickness、orientation 和 stage。检查零/负面积、惯性、密度、厚度和刚度。

## 5. 约束与刚体模态

构建约束矩阵或简化刚度图，检查：

- 预期刚体自由度；
- 约束线性相关；
- 零刚度机制；
- 过刚连接环；
- 对称边界；
- 单向和接触初始状态。

可执行无荷载小扰动或低阶特征值预检查。该结果只用于发现机制，不替代正式模态分析。

## 6. 荷载与质量预平衡

对每个 LC 和 stage 计算输入层面的总力、总矩、质量和重心。与节点 11 load resultant 和节点 08 mass ledger 比较。

## 7. 单位测试

至少执行以下适用测试：

- 单跨简化自重反力；
- 关键连接单位平动/转动；
- 支座导向方向单位荷载；
- 对称结构对称荷载；
- 索单元小扰动与拉力方向；
- 壳法向压力方向；
- prescribed displacement 反力方向；
- 阶段激活前后自由度和质量变化。

测试可以使用内部小型线性求解器或符号/解析计算，不依赖正式 solver deck。

## 8. 模型统计

输出节点、元素、自由度、约束方程、材料、截面、工况、组合、阶段、质量、连通分量和高敏感情景数量，为后续运行对比建立基线。

# 质量门

G11 通过条件：

1. schema、ID、引用、单位和坐标全部合法；
2. 无 CRITICAL 拓扑断链、孤立或误连；
3. 属性覆盖 100%；
4. 约束矩阵无非预期机制和相关性；
5. 荷载、质量和重心与 ledger 一致；
6. 所有强制单位测试通过；
7. 阶段激活和状态继承完整；
8. 数量级检查无异常；
9. 模型统计与 abstraction/component inventory 对账；
10. 检查脚本与阈值已记录。

# 失败处理

任何 CRITICAL 错误回到最早负责节点修订。例如质量重复回到节点 08 或 11，支座方向错误回到节点 09，拓扑断链回到节点 07。禁止在 solver deck 生成脚本中临时补节点、约束或荷载。

# 完成检查

1. 是否检查 schema 之外的物理一致性？
2. 是否完成单位和数量级扫描？
3. 是否将 load-path graph 映射到 FEM topology？
4. 是否检查刚体模态、机制和约束相关性？
5. 质量和荷载是否与 ledger 对账？
6. 是否执行关键连接、支座、索和阶段单位测试？
7. 是否输出可比较的模型统计基线？
8. 是否把错误路由回正确上游节点？

## 节点 14 · `bridge-solver-deck-execution`

来源：`skills/14-bridge-solver-deck-execution/SKILL.md`

---
name: bridge-solver-deck-execution
description: >
  将求解器无关的桥梁或猫道 FEM-IR 映射为指定软件输入文件，执行静力或阶段分析，固定软件版本、单位、特性映射、命令行、日志、重试和原始结果哈希。

# 任务

你负责求解器适配和可重放运行。该节点不重新解释图纸，不修改工程物理，只把已批准 FEM-IR 映射为 solver deck，并记录所有映射、警告、运行参数和原始结果。

# 输入契约

- analysis charter；
- G11=PASS/PASS_WITH_BOUNDS 的 FEM-IR；
- solver target、版本和许可证环境；
- adapter version 与 feature mapping matrix；
- numerical controls 和批准重试序列；
- 资源限制、并行设置和输出请求；
- clean run directory policy。

每个 solver entity 与结果字段映射要保留 FEM-IR 对象、sourceRef 链和适配器版本，支持双向审计。

# 输出工件

- `solver_deck_manifest.json`；
- solver input files；
- `feature_mapping_report.json`；
- `solver_run_record.json`；
- stdout、stderr、message、warning 和 convergence logs；
- `raw_result_manifest.json`；
- `deck_round_trip_report.json`；
- `solver_execution_issues.json`。

# 不可违反的规则

1. 只读取冻结 FEM-IR 和任务包列出的依赖。
2. 求解器、adapter、插件、材料库和操作系统版本全部记录。
3. 内部单位到求解器单位的转换只有一个入口，并生成审计表。
4. 每个 FEM-IR 特性必须映射为 supported、approved_equivalent 或 unsupported。
5. unsupported 关键特性不得静默删除或改写。
6. deck 生成脚本不能添加未在 FEM-IR 中存在的物理对象。
7. 求解设置变化必须属于预批准 retry sequence。
8. 每次运行使用干净目录和唯一 SOLVE-ID。
9. 原始结果文件只读保存并计算哈希。
10. “程序返回 0”只表示运行完成，不代表解通过验证。

# 工作顺序

## 1. 能力匹配

将 FEM-IR 中的 element、material、connection、contact、initial state、stage、load、output 和 nonlinear control 与 solver capability matrix 逐项匹配。

输出映射表：

- IR object/feature；
- solver keyword/API；
- 参数和单位转换；
- 语义差异；
- 验证测试；
- 支持状态。

任何关键 unsupported 项立即 `BLOCKED`。

## 2. 生成 deck

使用确定性模板或 API 创建：

- 节点、元素、材料、截面；
- orientation、offset、MPC、spring、contact、BC；
- initial stress/strain、prestress、form-found geometry；
- load cases、combinations 或 stage steps；
- solver controls；
- output requests。

对象名包含稳定 ID，便于结果回映射。

## 3. deck 静态检查

在运行前解析生成 deck，检查对象数量、坐标范围、属性、荷载总量、约束、阶段和输出请求与 FEM-IR 一致。生成 round-trip diff。

允许差异只包括求解器语法、内部排序和批准的等效展开。

## 4. 执行环境

记录：

- 主机/容器镜像；
- CPU、内存、线程；
- 求解器可执行文件哈希；
- 许可证配置摘要；
- 环境变量；
- 命令行；
- 开始/结束时间；
- 随机种子，若适用。

## 5. 正式运行

执行 baseline。实时捕获收敛、奇异、负特征值、接触、单元畸变、零主元、刚度比和能量警告。

## 6. 批准重试

若运行失败，按 numerical controls 中的顺序尝试，例如减小步长、启用批准线搜索、提高迭代上限。每次重试：

- 生成新 SOLVE-ID；
- 保存变更字段；
- 保留失败结果；
- 禁止改材料、截面、荷载、边界、初始状态和物理单元。

达到最大次数后 G12=`BLOCKED`。

## 7. 原始结果登记

登记数据库、二进制结果、文本输出、重启动文件、日志和后处理索引。计算 sha256，保存求解器单位、坐标约定和结果字段说明。

# 质量门

G12 通过条件：

1. 所有关键 FEM-IR 特性有合法映射；
2. deck round-trip 与 FEM-IR 一致；
3. 求解器和 adapter 版本固定；
4. 单位转换审计通过；
5. baseline 或批准重试成功完成；
6. 没有未处理的 fatal/critical solver warning；
7. 原始结果和日志完整且有哈希；
8. 运行环境可重建；
9. 多情景、多网格和多阶段均有独立 run record；
10. 未发生物理输入的隐式修改。

# 失败处理

若 deck round-trip 发现对象数量、荷载或边界不一致，修复 adapter 并重新生成，不能手工编辑 deck 后继续。若 solver warning 指向模型机制、错误接触或负刚度，返回 G11 或更早节点处理。

# 完成检查

1. 是否逐项核对 solver feature support？
2. 单位转换是否集中且可审计？
3. deck 是否通过回读对比？
4. 每次运行是否有唯一 ID 和干净目录？
5. 是否保存完整命令、环境和日志？
6. 重试是否只改变批准数值设置？
7. 原始结果是否只读并带哈希？
8. 是否避免把运行成功等同于工程通过？

## 节点 15 · `bridge-solution-verification`

---
name: bridge-solution-verification
description: >
  对桥梁或猫道求解结果执行残差、反力平衡、自由体平衡、能量、收敛、网格、步长、路径、模式和异常结果检查，确认数值方程得到足够可靠的解。

# 任务

你负责解验证。该节点回答“离散方程是否被充分求解、结果是否满足平衡、关键输出是否对网格和数值设置稳定”。它不承担规范承载力判断。

# 输入契约

- analysis charter 与 control metrics；
- FEM-IR；
- solver run record、日志和 raw result manifest；
- convergence plan；
- pre-solve verification 基线；
- 粗、基准、细网格结果；
- 多情景和多阶段结果。

每项验证检查要引用结果字段、FEM 对象、工况和 sourceRef/provenance 链，确保异常可追到输入与模型。

# 输出工件

- `solution_verification_report.json`；
- `verified_result_set.json`；
- `global_equilibrium_report.json`；
- `substructure_free_body_report.json`；
- `mesh_and_step_convergence_report.json`；
- `solver_warning_disposition.json`；
- `solution_issues.json`。

# 不可违反的规则

1. 结果解析器要记录 solver field 到 IR quantity 的映射和单位转换。
2. 全局反力平衡必须同时检查力和力矩。
3. 非线性分析检查每个增量的残差和路径，不只检查最终步。
4. 网格收敛使用预先定义的 control metrics，禁止求解后挑选较稳定指标替代失败指标。
5. 局部应力奇异点不能直接作为整体模型收敛判断。
6. solver warning 必须逐条分类和处置。
7. 对称性、符号、方向和极限情形属于强制 sanity check。
8. 多求解设置差异超过阈值时不得只选较顺眼结果。
9. 任何后处理平滑、平均和外推方式要明确。
10. 未通过 G13 的结果不得进入规范复核。

# 工作顺序

## 1. 结果完整性

检查所有请求工况、组合、阶段、情景和网格是否有结果；检查数据库是否截断、字段缺失、单位未知或对象映射失败。

## 2. 求解残差

提取每个 step/increment 的：

- force residual；
- displacement correction；
- energy residual；
- contact penetration 或约束误差；
- 迭代次数和 cutback；
- 负特征值或刚度变化。

与 numerical controls 阈值比较。

## 3. 全局平衡

对每个工况和阶段计算：

- 外荷载总力、总矩；
- 支座、锚固、基础反力总力、总矩；
- 惯性或等效作用，若适用；
- 不平衡绝对值和相对值。

同时按全局坐标和关键局部坐标检查。

## 4. 自由体平衡

在主梁、桥塔、墩、锚碇、猫道单跨、门架、索段和关键节点域切分自由体，比较边界内力、外荷载和连接力。该检查可发现全局平衡掩盖的局部误连。

## 5. 变形与符号

检查：

- 荷载方向与位移方向；
- 对称荷载的对称响应；
- 反对称工况的反对称响应；
- 支座自由方向位移；
- 索力拉力正号；
- 梁端内力和壳法向符号；
- 变形图是否沿传力路径连续。

## 6. 网格收敛

按 convergence plan 比较 coarse/baseline/fine：

- 位移、反力、构件内力、索力和稳定量；
- 截面合力或路径平均应力；
- 初始状态误差；
- 关键连接相对位移。

计算相对差、绝对差和收敛趋势。需要时使用 Richardson 外推或误差指标，方法和适用前提要说明。

## 7. 步长与算法敏感性

非线性模型至少比较一个更小步长或替代批准算法。检查路径、极值和最终状态是否稳定。若存在屈曲、松弛、接触切换或 snap-through，使用适用路径控制并报告分支。

## 8. solver warning 处置

将警告分为：

- benign with evidence；
- numerical concern；
- modeling concern；
- fatal。

每条警告绑定日志位置、影响对象、验证结果和关闭依据。禁止批量忽略。

## 9. 生成 verified result set

只有通过检查的工况、阶段、对象和字段进入 verified result set。任何受限结果带 caveat、适用范围和 issueRef。

# 质量门

G13 通过条件：

1. 结果字段完整、单位和对象映射正确；
2. 求解残差满足预设阈值；
3. 全局力和力矩平衡通过；
4. 关键自由体平衡通过；
5. 变形、符号、对称性和传力路径合理；
6. control metrics 达到网格收敛要求；
7. 非线性步长/算法敏感性可接受；
8. solver warnings 全部处置；
9. 多情景结果均完成相同验证；
10. verified result set 明确标注限制。

# 失败处理

残差或平衡失败时，先判断结果解析、荷载映射、约束、拓扑、非线性控制或单元质量的责任节点，并返回修订。禁止通过结果归一化、手工调整反力或删除异常工况获得通过。

# 完成检查

1. 是否检查所有工况、阶段、情景和网格结果完整性？
2. 是否同时校核力与力矩平衡？
3. 是否执行关键子结构自由体平衡？
4. 是否检查变形方向、符号和对称性？
5. 是否按预设 metrics 完成网格收敛？
6. 非线性路径和步长是否稳定？
7. 每条 solver warning 是否有处置？
8. verified result set 是否排除未验证字段？

# 不可违反的规则

1. 结果提取规则在读取结果前冻结，包括位置、坐标系、符号、分量、平均方式和包络逻辑。
2. demand 与 capacity 分开计算、分开存储，并在 check matrix 中引用；禁止只保留利用率。
3. 每个验算规则必须绑定批准 rule pack、正式来源定位和哈希。
4. 所有单位换算由确定性程序执行，记录原单位、目标单位和转换版本。
5. 梁、壳、实体、索和连接结果采用与其物理含义匹配的提取方法。
6. 阶段结果不得与未激活构件、不同参考构形或不同累计约定混包络。
7. 正负极值、方向极值、绝对极值和范围值分别定义，禁止互相替代。
8. 对非线性工况，组合方式必须与求解策略一致；不得对不能线性叠加的结果做代数组合。
9. 初始张力、预应力、恒载、阶段累计和增量结果的基准必须明确。
10. 接近限值的结果保留足够有效数字和未舍入值；判定使用未舍入值。
11. 缺失的局部检查进入 model external check register，并说明所需输入、责任人和对发布的影响。
12. 一项强制验算缺数据、缺规则或缺适用条件时，结论进入 `BLOCKED`。
13. 任何人工覆盖都要形成 override record，包含理由、批准人、前后值和影响分析；人工覆盖不能修改源结果。
14. 图表、云图和摘要中的数值必须能回链到 responseId 或 checkId。

# 工作顺序

## 1. 冻结结果提取计划

从 response metric register 生成 extraction manifest。逐项定义：

- 对象集合与 componentId；
- 节点、单元端、积分点、截面切面、壳路径或区域；
- 全局、构件局部、截面局部或索局部坐标；
- 正方向和符号约定；
- 端部偏置、刚域、释放和 eccentricity 的处理；
- 节点值、积分点值、截面合力、面积平均、路径平均或热点外推；
- 极值类型和包络维度；
- 允许参与的 stage、case、combination、scenario 和 mesh level。

extraction manifest 经过 schema 校验和规则完整性检查后锁定。后续修改产生新版本并重跑全部相关提取。

## 2. 校核结果资格

对每个拟用结果确认：

- 存在于 verified result set；
- 对象映射唯一；
- 单位和坐标系已解析；
- 工况、组合、阶段和情景状态完整；
- 结果未被 G13 caveat 排除；
- 提取位置没有跨越断面、铰、材料分界或激活边界。

不合格字段写入 exception register，并从正式包络中排除。

## 3. 生成响应与包络

按 metric 生成原子 response record，再执行包络。至少区分：

- 最大正值、最小负值和最大绝对值；
- 同时性要求下的伴随内力；
- 构件端、跨中、塔底、塔顶、支点、锚固点和控制截面；
- 各施工阶段峰值与最终阶段值；
- 各参数情景峰值；
- 服务状态、承载状态及项目定义的其他状态；
- 索力最大值、最小值、松弛裕度和张力变化；
- 支座最大/最小竖向反力、横向反力、纵向反力、位移和可能抬离；
- 猫道控制挠度、索力、横向位移、门架与锚固作用。

需要伴随效应时，在同一结果帧读取，禁止把各分量独立极值拼接成虚构组合。

## 4. 执行响应 sanity check

在规范验算前检查：

- 总体变形和控制点位移与节点 15 一致；
- 截面内力沿构件分布连续，连接、集中荷载和支承位置的跳变有物理依据；
- 截面切面合力与邻近梁单元内力或自由体结果相容；
- 壳积分后的膜力、弯矩和剪力与整体传力路径相容；
- 索力沿无分布荷载索段的变化符合平衡；
- 支反力包络与全局平衡报告相容；
- 对称和反对称工况仍保持预期特征；
- 量级与独立估算处于同一合理区间。

异常先返回节点 15、12、09 或 11定位，禁止直接进入利用率计算。

## 5. 计算作用效应

根据批准 rule pack 处理：

- 组合与包络选择；
- 有效宽度、截面分类、二阶效应放大或稳定相关效应，若在允许范围内；
- 施工阶段累计、预应力损失或温度基准，若已有批准算法；
- 局部坐标转换、截面最不利点应力恢复；
- 轴力—弯矩—剪力—扭矩相互作用所需 demand vector；
- 疲劳幅、动力放大或稳定结果仅在 charter 明确纳入时处理。

每一步保留中间变量、单位、公式版本和 rule trace。

## 6. 计算抗力或允许限值

capacity ledger 逐项记录：

- 材料设计参数和来源；
- 几何与截面参数来源；
- 有效长度、边界条件、长细比或局部板件参数；
- 抗力分项系数、修正系数与适用条件；
- 施工、腐蚀、温度、疲劳或临时状态修正，若适用；
- 公式输入、中间结果、最终抗力和单位；
- 规则有效域检查。

规则输入超出适用域时，停止该项计算并登记异常。

## 7. 形成设计检查矩阵

矩阵至少按以下维度可筛选：

- component、member、section、connection、support、cable segment；
- use case 与 limit state；
- stage、combination、scenario；
- check type 与 rule；
- demand、capacity、utilization、margin；
- decision、governing case、sourceRefs、assumptionRefs、issueRefs。

判定枚举使用：

- `PASS`：需求满足限值，且证据、规则和适用域完整；
- `PASS_WITH_BOUNDS`：所有批准参数边界内均满足，且边界条件已写入允许用途；
- `BLOCKED`：任何批准边界越限，或强制信息不足；
- `NOT_APPLICABLE`：经 charter 明确排除。

不得使用“仅超出很少”“工程上可接受”等无批准依据的替代判定。

## 8. 处理局部模型外检查

对整体模型无法直接支持的项目，创建 external check item：

- 局部对象与 drawing location；
- 上游 demand vector 和提取规则；
- 需要的局部几何、材料、接触或连接数据；
- 推荐的解析、组件模型或实体子模型方法；
- 规则包与验收标准；
- 责任角色、状态和发布阻断属性。

当该检查属于 charter 的强制范围时，未关闭状态导致 G14=`BLOCKED`。

## 9. 生成控制项与例外清单

对每个结构组给出：

- 最大利用率及其未舍入值；
- 控制截面、阶段、组合、情景和规则；
- 次控制项及与控制项的裕度；
- 对高敏感 assumption 的依赖；
- 模型适用限制；
- 未完成或例外检查。

控制项应能在图纸视图、模型视图和报告表格中使用同一稳定 ID 定位。

# 专项检查提示

## 梁、桁架、拱和塔柱

优先使用截面合力和 approved section properties。检查端部局部峰值是否来自刚域、偏心或约束；需要构件设计时，使用构件轴线、有效长度和真实边界条件。杆系模型不直接给出板件局部屈曲、焊缝热点或孔边应力结论。

## 箱梁与壳模型

定义壳法向、局部 1/2 方向、积分层和结果平均区域。整体截面验算优先由闭合截面切面合力恢复，局部板件验算使用经批准的板带、路径或子模型结果。奇异角点与集中约束附近结果单独登记。

## 悬索桥、斜拉桥与猫道索系

检查索力均为物理允许的拉力状态；对可能松弛的构件报告最小张力和发生阶段。索力、线形和支承反力必须对应同一初始状态情景。索夹、鞍座、锚具、散索鞍和局部弯曲需要专门规则或局部模型时，进入 external check register。

## 支座、伸缩与锚固

同时提取力、位移、转角和接触状态。检查设备允许值的来源、方向定义、正负容量和组合规则。出现抬离、滑移、间隙闭合或摩擦切换时，使用非线性结果路径，禁止用线性组合代替。

## 施工阶段和临时结构

逐阶段检查已激活构件、临时支承、张拉、拆除和体系转换。任何阶段的超限都不能由最终成桥状态通过抵消。猫道施工阶段应覆盖架设、面网与踏板安装、人员设备、抗风索或扶手索状态，以及经 charter 定义的风与温度情景。

# 质量门

G14 通过条件：

1. extraction manifest 已冻结，所有提取对象、位置、坐标、符号和平均方法明确；
2. 正式响应全部来自 verified result set；
3. response envelope 覆盖 charter 要求的全部阶段、组合、情景和指标；
4. demand 与 capacity 完整分离并可复算；
5. 每项规则绑定批准 rule pack、来源定位和哈希；
6. 规则适用域、单位、符号和组合逻辑通过确定性检查；
7. 控制项、伴随效应和未舍入判定可追溯；
8. 模型外强制检查已经关闭，或其阻断影响已明确；
9. 高敏感参数边界内结论一致；
10. exception register 没有未批准的严重项；
11. 摘要、表格和图形与机器工件一致；
12. static review summary 明确允许用途和限制。

任一强制规则、强制验算、关键结果资格或模型外检查缺失时，G14=`BLOCKED`。

# 失败处理

- 结果字段资格失败：返回节点 15；
- 响应量级、平衡或符号异常：返回节点 15，并追溯节点 11、09、08 或 07；
- 规则包缺失或未批准：返回节点 01，禁止临时编写系数；
- 构件映射不唯一：返回节点 05、06 或 07；
- 截面、材料或有效长度证据不足：返回节点 08 或 09；
- 局部行为超出整体模型能力：创建模型外检查，并按 charter 判定是否阻断；
- 情景边界内出现通过与不通过混合：状态设为 `BLOCKED`，交节点 17 做敏感性归因，不能选择较有利情景发布。

# 完成检查

1. 每个控制指标是否有预先冻结的提取规则？
2. 所有正式数值是否来自 verified result set？
3. 是否保留正负、方向、阶段、组合和情景维度？
4. demand、capacity、utilization 和 margin 是否均可独立复算？
5. 每项规则是否有正式来源定位、批准状态和哈希？
6. 是否检查规则适用域、量纲、符号与未舍入判定？
7. 是否避免将独立极值拼成虚构伴随效应？
8. 局部模型外验算是否全部登记并判定发布影响？
9. 控制项能否回溯到图纸、模型对象和原始结果？
10. G14 状态是否与 exception register 和所有强制检查一致？

# 任务

你负责最终技术保证。该节点要回答三个问题：

1. 主模型的关键响应能否由独立方法复现到预先设定的容差？
2. 关键结论对证据不确定性、建模假定、离散和算法选择是否稳健？
3. 当前证据足以支持哪些工程用途，哪些用途仍需额外验证或被限制？

独立复核、敏感性分析和可信度评估分别输出，再在 G15 汇总。三者不能互相替代。

# 输入契约

必须读取：

- analysis charter、风险等级、intended use、permissible use 和 acceptance criteria；
- 全部前序 gate ledger 与未关闭问题；
- abstraction decisions、FEM-IR、关键模型参数和 provenance；
- pre-solve 与 solution verification reports；
- verified result set、response envelopes、design check matrix 和 governing cases；
- assumption register、参数边界、证据等级与冲突处置；
- 网格、步长、求解器、规则包和工具链版本；
- 可用的试验、监测、荷载试验、既有审查模型或现场测量数据；
- 节点 01 规定的独立复核深度和审批角色。

每项独立输入和外部验证证据都要保留 sourceRef/provenance，禁止仅引用主模型摘要。

# 输出工件

- `independent_check_plan.json`；
- `independent_check_report.json`；
- `sensitivity_design.json`；
- `sensitivity_report.json`；
- `uncertainty_envelope.json`；
- `credibility_assessment.json`；
- `permissible_use_recommendation.json`；
- `independent_review_issues.json`。

# 独立性要求

独立证据至少在以下三个维度中满足两个：

- **方法独立**：解析法、降阶模型、影响线、索线方程、自由体、能量法、梁格/杆系与壳模型对比；
- **实现独立**：不同代码路径、不同脚本作者、不同建模工具或不同求解器；
- **数据解释独立**：独立读取关键图纸与输入，不直接复制主模型中间数值。

关键高风险结论优先满足三个维度。只更换输出格式、重复运行同一 deck、复制主模型节点后稀疏化、调用同一函数两次，均不能作为独立复核。

# 不可违反的规则

1. 独立复核计划在查看主模型详细结果前冻结方法、指标、容差和失败处置；需要看结果才能选方法时，记录潜在确认偏差。
2. 独立模型只包含验证目标所需物理，并明确其适用假设和预期差异。
3. 对比使用同一物理量、位置、坐标、符号、阶段、荷载基准和组合定义。
4. 差异用绝对值和相对值同时评价；近零量不单独使用相对误差。
5. 容差来自 charter、方法预期精度或经批准的验证计划，禁止事后放宽。
6. 敏感性参数来自 assumption register、模型选择和风险分析，禁止只挑容易变化且不影响结论的参数。
7. 参数范围必须有来源、物理可行性和相关性说明。
8. 高敏感参数需要覆盖边界，必要时包含联合不利情景；单参数扫描不能掩盖参数相关性。
9. 确定性安全系数、规范分项系数、统计不确定性和认识不确定性分开记录。
10. 只有试验或观测数据与模型用途、尺度、边界和响应相容时，才可作为 validation evidence。
11. 没有适用实测或试验数据时，可信度报告要明确 validation evidence 的空缺，并收紧 permissible use。
12. 可信度评分必须由证据项驱动，禁止用平均分掩盖任一关键项的阻断状态。
13. 独立检查人必须与主模型的关键建模、求解和正式复核保持项目规定的独立程度。
14. G15 结论需要独立检查人签认。

# 工作顺序

## 1. 识别控制结论

从 governing case register 和 design check matrix 提取：

- 最小裕度或最大利用率项目；
- 对安全、通行、施工或设备选择有直接影响的响应；
- 由复杂连接、初始状态、几何非线性、阶段转换或参数化边界控制的项目；
- 与规范限值接近的位移、索力、反力或构件作用；
- 前序 gate 中带 caveat 的结果；
- 模型外局部检查向整体模型回传的关键需求。

每个控制结论分配 `claimId`，随后所有独立证据、敏感性结果和可信度项都引用该 ID。

## 2. 建立独立复核计划

对每个 claim 选择至少一种方法：

- 静定或近似静定自由体平衡；
- 简支梁、连续梁、框架、桁架、拱或梁格降阶模型；
- 悬索线、抛物线索、悬链线或等效索网模型；
- 斜拉索轴力—刚度—几何关系；
- 猫道单跨、连续跨、门架—锚固体系或侧向抗风体系简化模型；
- 影响线、单位荷载、虚功或能量法；
- 独立截面属性与质量手算；
- 第二有限元求解器或不同单元族；
- 试验、监测、荷载试验或既有审查模型对比。

计划记录：输入来源、独立性维度、理想化、预期误差、比较 metric、容差、通过准则和责任人。

## 3. 独立重建关键输入

独立检查人从证据图读取控制参数：

- 跨径、标高、支承位置和关键偏心；
- 材料与截面属性；
- 质量和荷载；
- 边界、释放、连接刚度和索系初始条件；
- 组合或阶段定义。

与主模型输入比较，并将数据解释差异单列。发现图纸理解冲突时，先回到节点 04 或 05 解决，不能用调参让结果靠近。

## 4. 执行独立计算

计算过程必须：

- 使用可复算公式、脚本或第二模型；
- 保存输入、代码、版本和运行记录；
- 输出与 claim 对齐的 metric；
- 保留中间平衡量和关键假设；
- 对预期差异给出方向性解释。

对猫道或索系，至少检查自重或规定分布荷载下的线形、水平分力、支点张力、垂度和锚固反力之间的相容性。对整体桥梁，至少覆盖总反力、控制位移和一组主要构件内力。

## 5. 比较与差异归因

对每个 metric 计算：

- 主模型值与独立值；
- signed difference；
- absolute difference；
- relative difference，适用于分母远离零；
- normalized difference，使用 charter 定义的工程尺度；
- tolerance 和 decision。

差异按以下来源归因：

- 物理理想化；
- 几何与偏心；
- 边界或连接；
- 荷载分配；
- 初始状态；
- 离散与数值算法；
- 结果提取；
- 规范后处理；
- 输入解释错误或实现缺陷。

无法解释的关键差异导致 `BLOCKED`。

## 6. 设计敏感性分析

建立候选因素清单：

- 高敏感 assumption；
- 连接与支承刚度、摩擦、间隙和释放；
- 索初张力、目标线形、温度、弹性模量和有效面积；
- 材料模量、密度、截面尺寸和刚度折减；
- 边界土弹簧或基础刚度；
- 荷载位置、分布、同时性和施工顺序；
- 偏心、刚域、有效长度和构件激活时点；
- 网格、单元公式、积分、非线性步长和收敛容限；
- 规范规则中经批准的离散选择。

对每个因素记录 nominal、lower、upper、distribution 或 scenario、来源、相关组和可控制性。

按风险选择方法：

- 单因素边界扫描，用于单调性与局部影响；
- 设计试验或 Latin hypercube，用于多因素交互；
- 扰动导数或归一化敏感系数，用于局部排序；
- 极端情景组合，用于发布边界；
- 概率传播，仅在分布有依据且 charter 要求时使用。

## 7. 计算敏感性与稳健性

对每个 claim 报告：

- 响应范围、利用率范围和最不利情景；
- 参数—响应单调性与交互；
- normalized sensitivity index；
- 结论是否发生 PASS/BLOCKED 翻转；
- governing case 是否切换；
- 哪些不确定性主导总包络；
- 需要补充调查、试验或图纸确认的参数价值。

边界内出现判定翻转时，不能发布单一 nominal 结论。可通过补证、设计修改、限制用途或保守边界规则关闭。

## 8. 形成不确定性包络

将以下来源分别列示：

- 输入测量与图纸解释；
- 材料与截面；
- 边界与连接；
- 初始状态与施工过程；
- 模型形式；
- 离散和数值解；
- 结果提取与规则实现；
- 试验或观测误差，若有。

禁止在缺少统计依据时将全部项合并成伪精确概率。可以使用情景包络、区间、上下界或经批准的概率方法。每种合并方法要说明相关性处理和保守性。

## 9. 评估模型可信度

按每个 intended use 分项评价：

1. **用途与验收定义**：用途、决策、指标和容差是否明确；
2. **来源与输入谱系**：图纸版本、证据定位、单位和冲突是否受控；
3. **概念模型**：结构体系、传力路径、抽象、边界和物理范围是否充分；
4. **代码与工具验证**：解析器、几何程序、规则引擎、适配器和脚本是否通过单元/基准测试；
5. **计算验证**：网格、步长、残差、平衡和独立实现是否充分；
6. **实验或现场验证**：是否有与用途相容的 referent data，以及差异是否可解释；
7. **不确定性量化**：关键参数、模型形式和数值误差是否已包络；
8. **稳健性与敏感性**：结论对合理变化是否稳定；
9. **历史与相似性证据**：同类模型、既有项目或审查经验是否适用；
10. **管理与可复现性**：版本、审批、审计、变更和复跑是否受控。

每项使用证据等级：

- `E0`：无证据；
- `E1`：间接或未充分核验；
- `E2`：与用途相关且已核验；
- `E3`：强直接证据，经过独立审查或实测支持。

每项同时给出 criticality。高关键项为 E0 或存在未关闭严重 issue 时，该 intended use 不能获得发布通过。总览可以展示等级分布，最终判定按最弱关键项、claim 结果和 acceptance criteria 联合决定。

## 10. 提出允许用途建议

对每个 intended use 给出：

- `recommendedStatus`；
- 支持证据与独立复核范围；
- 参数边界与适用阶段；
- 可接受精度或容差；
- 未覆盖的物理和局部行为；
- 需要持续监测或现场确认的项目；
- 超出边界时触发的新分析。

建议不能扩大 analysis charter 原有范围；扩大用途需要返回节点 01 创建新版本。

# 质量门

G15 通过条件：

1. 所有高风险 claim 已有预先冻结的独立复核方法；
2. 独立检查满足项目要求的独立性维度；
3. 关键输入已独立读取并完成差异核对；
4. 主模型与独立结果在批准容差内，或差异有可验证的物理解释；
5. 所有高敏感 assumption、关键模型选择和数值选择已进入敏感性分析；
6. 参数边界具有来源、物理可行性和相关性说明；
7. 不确定性包络覆盖控制结论，且没有隐藏判定翻转；
8. 每个 intended use 完成可信度分项评价；
9. validation evidence 的存在或空缺得到明确陈述；
10. 所有高关键可信度项达到项目最低证据要求；
11. permissible use recommendation 与证据、限制和 gate 状态一致；
12. 独立检查人完成签认。

出现无法解释的关键差异、参数边界内判定翻转、关键证据 E0、独立性不足或检查人未签认时，G15=`BLOCKED`。

# 失败处理

- 独立输入与主模型不一致：返回相应源节点纠正，并重跑受影响子图；
- 独立方法精度不足：选择更高保真但仍独立的方法，保留原失败记录；
- 第二求解器功能不等价：缩小对比范围到可比物理，不能把不可比差异解释为通过；
- 敏感性边界来源不足：补充图纸、试验、制造公差、现场测量或批准假定；
- 结论对单一参数高度敏感：提出补证、监测、设计裕度或用途限制；
- 无适用 referent data：明确证据空缺，依靠更强 verification、独立复核和保守边界，并限制 validation 声明；
- 关键 issue 未关闭：保持 `BLOCKED`，不得用综合评分冲淡。

# 完成检查

1. 是否为每个高风险 claim 建立独立复核？
2. 独立方法是否真正分离了方法、实现或输入解释错误源？
3. 比较量是否在位置、坐标、符号、阶段和基准上完全一致？
4. 容差是否在结果比较前冻结？
5. 所有高敏感假定和关键数值选择是否已覆盖？
6. 是否分析参数相关性、控制组合切换和判定翻转？
7. 不确定性合并是否避免无依据的概率精度？
8. 可信度评价是否按 intended use 和关键证据项展开？
9. 是否清楚区分 verification evidence 与 validation evidence？
10. 允许用途建议是否与最弱关键证据和未关闭问题一致？
11. 独立检查人是否完成签认？

# 不可违反的规则

1. 原始来源、原始求解结果和已签认工件只读保存；发布节点不得修改上游数值。
2. 报告中的数字、表格和图形由正式机器工件生成，禁止手工重录控制值。
3. 每个结论、表格行和关键图形至少引用 responseId、checkId、claimId 或 artifactId。
4. release manifest 必须列出每个文件的相对路径、字节数、SHA-256、MIME 类型、生成工具和来源工件。
5. 报告明确 intended use、permissible use、excluded use、适用阶段、版本和限制。
6. 所有 gate 状态、边界通过条件、未关闭 issue 和批准例外必须进入报告，禁止只展示通过项。
7. 报告摘要与机器数据使用同一决策枚举和同一未舍入判定来源。
8. 图纸、规范、rule pack、脚本、环境、求解器、后处理器或假定变更都要生成新 run 或新 release；禁止覆盖旧发布包。
9. 变更影响从首个变化工件沿依赖图传播；任何手工缩小影响范围都需要工程依据和批准。
10. 节点 13、15、17、18 的 gate 在受影响重跑后强制复评。
11. 签名记录要包含签认角色、人员、范围、时间、工件哈希和签名机制。
12. 发布状态只能基于 gate ledger 自动汇总；报告措辞不能改变 gate 结论。
13. release bundle 必须在干净环境完成哈希校验和最小复现测试。
14. 包含受限或敏感资料时，按项目数据分级生成脱敏交付包，并保留内部完整包的映射。
15. 任何 superseded release 必须保留并标记替代关系、原因和生效日期。

# 工作顺序

## 1. 冻结发布候选

创建 `releaseCandidateId`，记录：

- projectId、runId、releaseId 和语义版本；
- 候选工件集合及哈希；
- 报告模板版本；
- 工具链与环境锁；
- 计划签认角色；
- 交付范围和数据分级。

冻结后新增或修改上游工件会使候选失效，必须重建候选。

## 2. 汇总 gate 与 issue

按 DAG 顺序汇总 G0–G16：

- gate 状态、评价时间、评价程序版本；
- 强制条件结果；
- caveat、bound 和 issueRefs；
- 审批状态；
- 影响的 intended use。

issue 按 severity、owner、due state、blocking、affected claims 和 closure evidence 分类。任何 blocking issue 未关闭时，release 状态为 `BLOCKED`。

## 3. 建立依赖与证据追踪

生成两张图：

- artifact dependency graph：工件级输入—输出依赖；
- claim trace graph：工程结论到 check、response、result、FEM object、abstraction、component 和 source evidence 的路径。

执行 orphan audit：

- 没有上游来源或 assumption 的模型对象；
- 没有结果依据的报告数字；
- 没有批准规则的验算；
- 没有 owner 的 blocking issue；
- 没有签认范围的关键工件。

存在关键 orphan 时禁止发布。

## 4. 生成工程报告数据层

先生成 `engineering_report_data.json`，禁止直接由聊天文本拼接最终报告。数据层至少包含：

- 项目、版本和用途；
- 采用资料与标准；
- 结构体系与模型范围；
- 抽象、单元、边界、初始状态、荷载、阶段和组合；
- 质量、网格、模型统计与求解设置；
- 求解前检查、解验证和独立复核；
- 控制响应、控制验算和利用率；
- 敏感性、不确定性和可信度；
- 假定、例外、限制和未关闭问题；
- 审批与签名。

所有 quantity 保留数值、单位、显示精度和 source reference。显示格式由模板控制，工程判定始终使用原始未舍入值。

## 5. 生成工程报告

报告建议结构：

1. 封面、版本、签认与修订记录；
2. 执行摘要与工程结论；
3. intended use、允许用途和排除用途；
4. 资料、图纸版本、标准与规则包；
5. 结构体系、施工阶段与传力路径；
6. 有限元抽象、几何、材料、截面、质量、连接和支承；
7. 初始状态、荷载、组合和施工阶段；
8. 单元、网格、求解器和数值控制；
9. 模型验证与解验证；
10. 静力响应与规范复核；
11. 独立复核、敏感性、不确定性和可信度；
12. 假定、限制、例外和未关闭问题；
13. 结论、使用条件和后续动作；
14. 附录：输入清单、模型统计、控制表、gate ledger、trace index。

执行摘要必须给出结构阶段、作用范围、控制位置、控制组合、最小裕度、关键边界和发布状态。禁止只写笼统结论。

## 6. 生成图形和表格

图形至少覆盖：

- 结构总体、坐标和构件 ID；
- 图纸—模型叠合或关键几何核验；
- 边界、释放、连接、索系和荷载示意；
- 变形、内力、索力、反力和控制位置；
- 网格收敛、敏感性和独立结果对比；
- 结论追踪与变更影响图。

每幅图带 figureId、数据工件哈希、case/stage/scenario、单位、比例、变形放大倍数和生成脚本版本。云图色标范围与裁剪规则固定并写入元数据。

表格由结构化数据生成，控制值包含完整定位和 governing case。分页、排序或显示舍入不得改变数据语义。

## 7. 组装机器发布包

复制正式工件、脚本和必要运行环境描述。保留：

- JSON/YAML/CSV 等开放机器格式；
- 求解器原生 deck 与版本信息；
- 原始结果的 manifest、哈希和存储定位；
- 后处理脚本与 rule pack；
- schema、workflow 和 Skill 版本；
- 最小可复现实例或 smoke test；
- 第三方依赖清单和许可证说明，若适用。

大型原始数据库可以采用内容寻址外部存储，release manifest 仍需记录 URI、哈希、大小、访问控制和保留策略。

## 8. 编写复现运行手册

runbook 至少说明：

- 支持的操作系统或容器；
- 依赖安装与环境锁；
- 输入工件路径和哈希校验；
- workflow 启动命令；
- solver license 与版本要求；
- 预期节点、运行状态和关键日志；
- 结果解析、gate 重算和报告生成命令；
- 最小 smoke test 的预期输出；
- 常见失败与不得采用的绕过方式。

命令中的路径、参数和版本必须可直接执行，秘密信息使用安全注入方式，禁止写入发布包。

## 9. 执行发布验证

在干净环境或受控容器中执行：

- 文件完整性与哈希校验；
- JSON Schema 和 YAML 解析；
- ID、引用与依赖完整性；
- gate 自动汇总一致性；
- 报告数值与机器工件逐项抽查；
- 图表 source reference 校验；
- 最小 smoke test 或选定控制 metric 复现；
- 安全、权限、敏感信息与恶意宏检查；
- 文件可打开性和字符编码检查。

验证报告记录环境、工具、结果、差异和批准例外。

## 10. 完成签认与发布

签认顺序遵循 approval matrix。签认人确认的范围至少包括：

- analysis lead：用途、模型和工程结论；
- checker：独立复核与关键结果；
- approver：发布范围、限制和剩余风险；
- data/configuration role：完整性、版本和复现。

签认后生成不可变 release manifest 和 checksum 文件。任何内容变化使签名失效，并进入新 release。

# 变更控制

## 1. 变更分类

每项 change request 记录类型：

- source drawing/revision；
- standard/rule pack；
- analysis purpose/acceptance；
- evidence interpretation/component inventory；
- geometry/material/section/mass；
- connection/boundary/initial state；
- load/combination/stage；
- element/mesh/numerics；
- solver/toolchain/parser；
- result extraction/check/report；
- issue closure or approval。

同时记录变更原因、发起人、时间、旧值、新值、sourceRef 和批准状态。

## 2. 影响传播

从首个 changed artifact 沿 workflow 和 claim trace graph 传播。默认规则：

- 输入文件变化：从 N02 或更早的语义节点开始；
- 规范、限值或用途变化：从 N01 开始；
- 图纸解释变化：从 N04 或 N05 开始；
- 抽象变化：从 N06 开始；
- 几何、材料、连接、初态、荷载或网格变化：从对应节点开始；
- solver 或 parser 版本变化：至少重跑受影响适配、验证和报告节点；
- 仅报告排版变化：可以只重跑 N18，但必须证明数据层未改变。

所有路径最终重评 G11、G13、G15 和 G16。若控制 claim、利用率或允许用途受影响，发布版本至少提升项目规定的相应级别。

## 3. 差异报告

每次重跑生成 machine diff 与 engineering diff：

- 工件新增、删除和哈希变化；
- 模型对象、参数、荷载和组合变化；
- 模型统计与质量变化；
- 控制响应、控制组合和利用率变化；
- gate、issue、可信度和允许用途变化；
- 报告文字与图表变化。

差异必须区分预期变化、连带变化和异常变化。异常变化未解释时不得发布。

## 4. 替代与撤回

新 release 记录 `supersedesReleaseId`。旧 release 保留状态：

- `ACTIVE`；
- `SUPERSEDED`；
- `WITHDRAWN`；
- `ARCHIVED`。

撤回需要记录原因、影响的工程决策、通知范围和替代方案。禁止删除曾用于正式决策的发布证据。

# 质量门

G16 通过条件：

1. G0–G15 的发布相关状态已自动汇总，任何 blocking issue 均已关闭；
2. 发布候选工件集合冻结，哈希和依赖完整；
3. engineering report data 与机器工件一致；
4. 报告完整说明用途、阶段、标准、模型、验证、控制结果、限制和例外；
5. 每个关键结论存在端到端 claim trace；
6. release bundle 通过 schema、引用、哈希、数值和安全校验；
7. runbook 与环境锁足以执行最小复现；
8. 变更影响图、supersession 和版本规则完整；
9. 所有签认角色按 approval matrix 完成签名；
10. release manifest 和 checksum 文件已冻结；
11. permissible use 与 G15 建议一致，未扩张分析范围；
12. release validation report 没有未批准严重项。

任何报告数值无法追踪、发布工件哈希不一致、签名缺失、blocking issue 未关闭、用途超出 G15 建议或复现校验失败时，G16=`BLOCKED`。

# 失败处理

- 报告与机器工件不一致：重建 report data 与报告，禁止手工修数字；
- 上游工件在候选冻结后变化：使候选失效，重新生成 release candidate；
- 哈希、引用或 schema 失败：返回产生该工件的节点修复，并保留失败记录；
- claim trace 断裂：补齐来源、模型映射或结果引用；无法补齐时阻断发布；
- smoke test 不可复现：冻结环境、工具版本和随机种子，追溯依赖或数值差异；
- 签认意见导致工程内容变化：创建新工件版本，重评受影响 gate；
- 仅需对外脱敏：从已签认内部包派生，记录删除/替换映射并重新做完整性校验；
- 已发布结果发现严重错误：立即标记 `WITHDRAWN`，生成影响清单并启动纠正 run。

# 完成检查

1. 发布包是否同时具备人可审查报告和机器可复现工件？
2. 报告中的每个控制数字是否由正式数据层生成？
3. 每个关键结论是否能追到 check、response、result、模型对象和源证据？
4. gate、issue、边界和限制是否完整披露？
5. 文件哈希、依赖、工具版本和环境是否冻结？
6. 是否在干净环境完成 schema、引用、哈希和 smoke test？
7. 签名是否绑定明确范围与工件哈希？
8. 变更影响是否从首个变化工件传播并重评强制 gate？
9. 新旧 release 的替代、撤回和保留状态是否明确？
10. 最终 permissible use 是否与 G15 和 analysis charter 一致？
