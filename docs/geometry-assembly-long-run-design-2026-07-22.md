# 桥梁几何装配长任务：分阶段生成、闭环反修与独立验收方案

日期：2026-07-22

适用范围：从工程图纸生成桥梁三维设计几何并完成装配验证。本文只讨论几何、装配、代理体、视觉检查和长任务编排，不进入有限元属性、荷载、求解或规范验算。

关联案例：`RUN-20260722-ZHAQING-STRICT-010`

## 1. 方案目标

本方案把工程人员“先定基准—分构件建模—按接口逐件装配—观察和量测—发现问题后反修—装完后整体复核”的过程转化为一个可持续运行、可暂停恢复、无需用户逐阶段发令的自动化长任务。

目标不是一次生成整座桥，而是保证：

1. 每一步只处理一个可验收的构件或子装配；
2. 代理盒子可以用于早期布局，但永远不能冒充设计几何；
3. 每个构件都经过确定性量测和独立视觉检查；
4. 锚碇等已经验收的构件不能被后续低保真版本覆盖；
5. 整个过程由一个确定性控制器自动推进，用户不需要在每个阶段重新下指令；
6. 会话压缩、上下文切换或子智能体更换不会改变已经冻结的工程事实；
7. 几何装配没有通过之前，流程不得进入 FEM。

## 2. 对 `STRICT-010` 的根因判断

`STRICT-010` 的直接失败不是“模型把图纸自动压缩成盒子”，而是自建生成器选择了 `make_box(minimum, maximum)` 作为主要几何表达，并将预览代理输出为 N07 几何事实。

长任务压力是风险放大因素，具体表现为：

- 为了维持表面进度，把完整设计几何降级成可显示预览；
- 用少量容易闭合的坐标替代大量尚未闭合的构造关系；
- 将同一生成器的输入重新作为检查依据，形成循环自证；
- 后续阶段重新生成整桥，覆盖此前较正确的锚碇或其他构件；
- 节点全部运行，但运行在错误的几何事实之上。

因此，修复重点不是禁止所有盒子，而是建立代理体的合法边界、单调细化规则、逐构件装配状态机和独立验收链。

## 3. 调研结论

### 3.1 长任务需要持久化工作状态，不能依赖对话记忆

长时智能体在多个上下文窗口中容易出现两种典型失败：一次尝试完成过多内容，以及看到已有成果后过早宣布完成。有效做法是由初始化阶段建立任务清单和进度文件，后续每次只完成一个增量工作包，并为下一次运行留下清晰、可检查的状态。

本方案采用相同原则：工程真值保存在文件化工件、哈希、版本链和检查回执中；对话摘要只保存进度，不保存坐标、尺寸或装配事实。

### 3.2 长任务应采用“计划—生成—评价”分工

长任务的可靠性通常来自分解、结构化交接和独立评价，而不是让一个智能体在同一上下文中同时计划、生成、检查和批准。

本方案采用一个确定性控制器，加三个主要智能体角色：

- 规划智能体：生成装配依赖、工作包和验收计划；
- 建模智能体：严格消费冻结输入，生成或修改当前构件；
- 独立评价智能体：只依据源图、模型渲染和确定性量测进行视觉复核。

确定性几何校验器不是智能体，由程序直接计算尺寸、接口、拓扑、覆盖率和版本退化。

### 3.3 CAD 生成必须由开环一次生成转为闭环迭代

近期 CAD 智能体研究普遍采用“生成—执行—观察—修正”循环。只使用视觉反馈可能漏掉精确尺寸错误，只使用包围盒、体积或拓扑统计又可能出现几何外观和装配语义错误。可靠方案需要同时使用：

- CAD 内核精确量测；
- 多视图渲染和图纸回投；
- 独立视觉评价；
- 可编辑、带约束和操作历史的参数化表示。

### 3.4 多智能体不是目的，权责分离才是目的

不建议把十九个 Skill 简单映射为十九个并行智能体。智能体数量越多，交接和一致性成本越高。本方案只拆分存在利益冲突的职责，并由一个确定性控制器维持唯一状态。

## 4. 总体架构

```text

                       │ 确定性装配控制器          │
                       │ 状态机、队列、检查点、回滚 │
                       └────────────┬─────────────┘
                                    │
              ┌─────────────────────┼─────────────────────┐
              │                     │                     │
     ┌────────▼────────┐   ┌────────▼────────┐   ┌────────▼────────┐
     │ 规划智能体       │   │ 建模智能体       │   │ 独立视觉评价智能体│
     │ 工作包/依赖/验收 │   │ 当前构件生成与反修│   │ 多视图盲审         │
     └────────┬────────┘   └────────┬────────┘   └────────┬────────┘
              │                     │                     │
              └─────────────────────┼─────────────────────┘
                                    │
                       ┌────────────▼─────────────┐
                       │ 确定性几何校验工具链      │
                       │ 配准、量测、接口、拓扑、   │
                       │ overlay、退化、代理扫描    │
                       └──────────────────────────┘
```

### 4.1 确定性装配控制器

控制器不负责工程判断和 CAD 创作，只负责：

- 读取机器可读工作流；
- 按依赖顺序领取工作包；
- 限制当前允许访问的源资料和工件；
- 调用建模、量测、渲染、视觉评价和反修；
- 在每次通过后冻结快照；
- 在失败时回到最早责任阶段；
- 在上下文压缩或新会话开始时恢复状态；
- 阻止越级进入后续阶段或 FEM。

### 4.2 规划智能体

规划智能体只在初始化和批准的变更影响分析时运行。它输出：

- 构件清单和稳定 ID；
- 子装配树；
- 依赖图；
- 每个构件的源图范围；
- 设计基准、局部坐标和接口契约；
- 允许使用代理体的范围和退出条件；
- 每个工作包的确定性验收项；
- 多视图和详图检查计划。

规划结果冻结后，建模智能体无权自行降低目标或改写验收项。

### 4.3 建模智能体

建模智能体每次只接收一个原子工作包。它可以：

- 新建当前构件；
- 将当前构件从代理体升级为骨架或设计实体；
- 根据结构化问题清单修改当前构件；
- 生成参数化建模代码和操作历史。

它不可以：

- 修改已冻结的源事实；
- 重新定义全桥坐标；
- 修改不在当前工作包中的构件；
- 用代理体覆盖已验收设计实体；
- 写 Gate 状态；
- 将“看起来合理”作为尺寸或接口依据。

### 4.4 独立视觉评价智能体

视觉评价智能体与建模智能体隔离。它只看到：

- 当前源图视图或详图；
- 固定相机和固定比例的模型渲染；
- 图纸回投 overlay；
- 由几何内核独立生成的尺寸标注；
- 当前构件接口和问题清单。

它不读取建模智能体的推理、手工常量或“为什么这样画”的解释，避免自我确认。

输出必须是结构化问题，不直接写 PASS：

```json
{
  "componentId": "CMP-ANCHORAGE-L",
  "viewId": "VIEW-ANCHORAGE-ELEVATION",
  "issueType": "CONTOUR_MISMATCH",
  "severity": "CRITICAL",
  "location": "upper cable-entry face",
  "observation": "model uses a vertical box face; drawing shows an inclined stepped face",
  "evidenceRefs": ["SRC-26:DETAIL-A", "RENDER-004", "OVERLAY-004"]
}
```

## 5. 三种几何表示必须分离

每个工程构件使用同一个稳定 `componentId`，但允许存在三类独立表示：

1. `displayProxy`：布局和可视化代理；
2. `designGeometry`：忠实表达图纸设计意图的几何；
3. `analysisGeometry`：未来 FEM 使用的参考线、中面、等效域和偏心。

三者不得共用一个几何对象，也不得通过重命名把代理体改称设计实体。

示例：

```json
{
  "componentId": "CMP-ANCHORAGE-L",
  "representations": {
    "displayProxy": "GEO-PROXY-ANCH-L-001",
    "designGeometry": "GEO-DESIGN-ANCH-L-004",
    "analysisGeometry": null
  }
}
```

几何装配阶段只允许 `displayProxy` 和 `designGeometry`。`analysisGeometry` 必须在设计几何验收后由后续流程单独产生。

## 6. 代理体的合法生命周期

代理盒子不是禁止项，但必须显式登记为技术债务。

### 6.1 表示等级

```text
MISSING
  ↓
PROXY
  ↓
REFERENCE_SKELETON
  ↓
DESIGN_COARSE
  ↓
DESIGN_REFINED
  ↓
VERIFIED
```

正常状态只允许向前提升。任何表示等级下降都必须被阻断。

### 6.2 每个代理体必须登记

- `componentId`；
- `representationLevel=PROXY`；
- 使用目的，例如总体占位、碰撞预算或相机构图；
- 代理形状类型，例如 AABB、OBB、中心线或简化面；
- 已知不真实的内容；
- 依赖的源事实；
- 缺少的源事实；
- 必须升级到的目标等级；
- 最迟退出阶段 `refineByStage`；
- 是否允许进入子装配；
- 是否允许导出；
- 所有者和问题编号。

### 6.3 代理体的硬规则

1. 代理体只能写入 `proxy/` 命名空间和代理清单；
2. 代理体不得写入 `designGeometry` 字段；
3. 代理体不得满足设计几何 Gate；
4. 代理体不得作为图纸回投通过的依据；
5. 代理体不得覆盖已存在的 `DESIGN_*` 或 `VERIFIED` 版本；
6. 最终装配冻结时代理数量必须为零；
7. 若算力或资料不足，只能以 `RESEARCH_PREVIEW/BLOCKED` 结束，不能降级放行。

## 7. 单调细化和防退化

“锚碇一开始正确，后来又变错”说明系统缺少单调性约束。

每个已验收构件必须形成只读快照：

```text
accepted/CMP-ANCHORAGE-L/rev-004/
  geometry.step
  native.FCStd
  parameters.json
  source_map.json
  interface_report.json
  overlay_report.json
  visual_review.json
  snapshot.sha256
```

后续修改不得原位覆盖。新版本必须：

- 使用新的 revision；
- 通过 `supersedes` 指向旧版本；
- 输出参数、轮廓、接口和体量差异；
- 说明修改原因和受影响下游构件；
- 重新执行当前构件及所有受影响子装配的检查。

退化校验器至少检查：

- 表示等级是否下降；
- 已验收非矩形实体是否被替换为 box/cylinder 等低保真代理；
- 接口点数量是否减少；
- sourceRefs 覆盖率是否下降；
- 原已通过的控制点是否发生未解释偏移；
- 子装配中是否出现旧版本和新版本混用。

任何退化都将新版本标记为 `REJECTED_REGRESSION`，旧的已验收版本保持有效。

## 8. 几何装配主流程

以下是几何依赖顺序，不等同于实际施工工序。整个流程由控制器自动连续运行，无需用户逐步确认。

### S00：初始化长任务

输出：

- `assembly_run.json`；
- `assembly_progress.json`；
- `component_manifest.json`；
- `subassembly_graph.json`；
- `representation_registry.json`；
- `proxy_ledger.json`；
- 冻结的源文件和契约哈希。

### S01：冻结全局基准和坐标

建立：

- 桥轴、跨界、里程方向；
- 绝对标高基准；
- 平面、立面、横断面视图变换；
- 左右岸和左右幅定义；
- 各子系统局部坐标；
- 控制点和配准残差。

此阶段必须明确诸如 `4129.04 m` 的物理含义，不能仅把它设置为 `z=0`。

### S02：冻结装配接口和构件工作包

每个构件必须定义：

- 父子装配关系；
- 支承、锚固、悬挂、接触或无连接语义；
- 连接点、连接线或连接面；
- 接口局部坐标；
- 允许偏差；
- 需要回投的图纸视图；
- 依赖构件和下游构件。

没有接口契约的构件不得进入正式几何生成。

### S03：基础与锚碇子装配

顺序：

1. 基础控制面和地基参考；
2. 承台、桩或基础实体；
3. 左右锚碇设计轮廓；
4. 主缆锚固点、锚面和进入方向；
5. 基础—锚碇—主缆接口检查。

锚碇允许先使用代理包络进行总体布局，但本阶段结束前必须升级为包含图纸斜面、台阶和关键锚固构造的设计实体。

### S04：索塔与索鞍子装配

顺序：

1. 塔基和塔柱控制轴；
2. 塔柱真实截面和高程变化；
3. 上下横梁；
4. 索鞍中心、槽线和局部坐标；
5. 塔—基础、塔—桥面、塔—索鞍接口检查。

### S05：桥面承重骨架子装配

顺序：

1. 桥面设计基准和结构参考面；
2. 横梁站位；
3. 纵梁轴线、截面和端部；
4. 塔端支承或连接；
5. 桥面板支承面；
6. 横梁—纵梁—桥面板接口检查。

不得将桥面设计线、桥面板顶面、梁顶面和吊杆连接面合并为同一 `z=0`。

### S06：主缆和索面子装配

顺序：

1. 左右主缆索面横向位置；
2. 锚点和索鞍控制点；
3. 分段曲线或受控参数曲线；
4. 主缆与锚碇、索鞍的切向和位置连续性；
5. 多视图线形回投。

吊杆长度或垂度不能反向自证主缆位置；主缆控制量必须有独立来源。

### S07：吊杆、抗风索和横向体系

顺序：

1. 吊杆上端接口；
2. 吊杆下端真实连接面或节点；
3. 抗风索桥面端和锚固端；
4. 横向联系；
5. 每条索的端点、方向、间距和装配检查。

### S08：桥面板和次要构件细化

按构件清单逐件或按重复规则实例化：

- 桥面板单元；
- 边框、加劲、栏杆和附属构件；
- 局部节点和连接件；
- 重复构件阵列及其稳定实例 ID。

### S09：整桥装配闭合

检查：

- 所有构件都进入唯一父装配；
- 所有必须接口闭合；
- 无未解释悬空、误接、穿透和过大间隙；
- 全桥对称、跨径、标高和横向位置闭合；
- 传力路径对应的几何接口连续；
- 不存在代理体替代设计实体。

### S10：代理清零和全局反修

控制器扫描 `proxy_ledger`。每个未关闭代理生成一个独立反修工作包，按其最早责任阶段返回处理。

不允许使用整体平移、整体缩放或全桥重新生成来消除局部问题，除非 S01 坐标基准本身被正式修订。

### S11：最终多视图验收和冻结

至少生成：

- 全桥平面；
- 全桥立面；
- 典型横断面；
- 左右锚碇详图；
- 左右索塔和索鞍详图；
- 桥面、横梁、纵梁和吊杆接口详图；
- 主缆和抗风索端点详图；
- 关键构件等轴测图。

每个视图同时包含模型渲染、图纸 overlay、控制点偏差和独立视觉评价结果。全部通过后冻结 `GEOMETRY-RELEASE-CANDIDATE`，但仍不等于 FEM 或工程发布。

## 9. 原子装配工作包

长任务的基本执行单位不是“整座桥”，而是一个构件或一个小型子装配工作包。

示例：

```json
{
  "workPackageId": "AWP-ANCHORAGE-L-004",
  "componentIds": ["CMP-ANCHORAGE-L"],
  "stage": "S03",
  "goalRepresentation": "DESIGN_REFINED",
  "sourceRefs": ["SRC-26:VIEW-01", "SRC-26:DETAIL-A"],
  "coordinateSystemId": "CS-ANCHORAGE-L",
  "dependencies": ["AWP-GLOBAL-DATUM-001"],
  "interfaceContracts": ["IFC-MAIN-CABLE-ANCH-L", "IFC-FOUNDATION-ANCH-L"],
  "allowedTools": ["freecad", "opencascade", "renderer", "overlay"],
  "forbiddenActions": ["modify_global_datum", "replace_other_components"],
  "acceptanceChecks": [
    "source_coverage",
    "contour_and_steps",
    "anchor_point_position",
    "cable_entry_direction",
    "multi_view_overlay",
    "visual_review",
    "no_regression"
  ],
  "repairBudget": 3
}
```

控制器自动执行：

```text
领取工作包
  → 读取局部源证据
  → 生成或修改当前构件
  → CAD 内核执行
  → 精确量测和接口检查
  → 固定多视图渲染
  → 图纸 overlay
  → 独立视觉评价
  → 形成结构化问题
  → 局部反修
  → 重新检查
  → 通过后冻结快照并领取下一个工作包
```

如果在修复预算内未收敛，当前工作包变为 `BLOCKED`。控制器可以继续执行与其无依赖关系的工作包，但不得跨过依赖它的装配阶段。

## 10. 双层闭环反修

### 10.1 内循环：执行和几何有效性

由建模智能体与 CAD 内核完成，处理：

- 代码语法和 API 错误；
- 实体生成失败；
- 非法 B-Rep；
- 空实体；
- 自相交；
- 布尔运算失败；
- 参数引用失效。

### 10.2 外循环：工程几何和装配真实性

由独立校验链完成，处理：

- 控制尺寸偏差；
- 错误参考面；
- 接口坐标或方向错误；
- 轮廓、台阶、斜面和开孔缺失；
- 构件错装、悬空或错误接触；
- 主缆、吊杆和索鞍不连续；
- 代理体未细化；
- 与前一已验收版本相比发生退化。

外循环的反馈必须定位到 `componentId + viewId + interfaceId + sourceRef`，禁止只返回“看起来不对”。

## 11. 确定性检查与视觉检查的分工

### 11.1 确定性检查

至少包括：

- 坐标变换和控制点残差；
- 尺寸链和标高链；
- 构件包围盒，但只作为辅助指标；
- 体积、面积、长度和实体有效性；
- 端点、轴线、面法向和切向；
- 连接点距离和接口重合；
- 间隙、穿透和净空；
- 装配图连通性；
- sourceRefs 覆盖率；
- 代理体数量；
- 表示等级和版本退化；
- 当前版本与已验收版本的几何差异。

### 11.2 视觉检查

至少检查：

- 整体比例和形态；
- 锚碇、塔柱、横梁等非矩形特征；
- 构件是否装在合理的父构件位置；
- 图纸轮廓与模型轮廓是否一致；
- 左右、上下、内外侧是否颠倒；
- 设计详图中难以完全结构化的构造关系。

视觉评价不能替代精确量测；精确量测也不能替代视觉和装配语义。

## 12. 长任务上下文管理

### 12.1 工程真值不进入自由文本摘要

以下内容必须从文件读取，不能只依赖对话：

- 接受坐标和标高；
- 尺寸和材料；
- 构件清单；
- 接口契约；
- 代理清单；
- 已验收版本；
- 当前问题；
- 工作包状态；
- Gate receipt 和哈希。

### 12.2 每次智能体调用只加载局部上下文

建模智能体只加载：

- 当前工作包；
- 当前构件涉及的源图；
- 直接依赖构件的已验收接口；
- 当前版本和上一次问题清单；
- 必要工具说明。

它不需要反复加载整套十九 Skill、全部图纸和全部运行日志。

### 12.3 会话压缩和恢复

`PreCompact` 保存：

- 当前工作包；
- 当前尝试编号；
- 最新工件哈希；
- 未关闭问题；
- 下一允许动作。

`PostCompact/SessionStart` 从 `assembly_progress.json` 恢复，而不是让模型根据摘要猜测进度。

### 12.4 自动连续运行

用户只需启动一次长任务。控制器在每个工作包完成后自动领取下一工作包。只有以下情况需要停止：

- 源资料存在无法自动消解的关键冲突；
- 连续反修没有改善；
- 需要改变已冻结的工程用途或坐标基准；
- 工具、契约或源文件哈希发生变化；
- 到达资源上限。

停止时输出精确阻断项，不要求用户重复下达后续节点指令。

## 13. 现有 hooks 能做什么、不能做什么

### 13.1 已有能力

当前 PR #6 的 hooks 可以：

- 维护 active run 和节点状态；
- 在上下文压缩后恢复任务包；
- 要求规定工件和 Gate receipt；
- 阻止专业节点直接写 Gate 状态；
- 阻止未实现条件被包装成 `PASS`；
- 阻止 N04–N13 未通过时进入求解；
- 阻止无回执的完成声明。

这些能力能够防止“没有证据仍然宣称完成”，但不能自行判断锚碇是否画对。

### 13.2 需要新增的几何 hook 层

建议在现有 `PreToolUse/PostToolUse/Stop` 上增加以下检查器：

#### A. 代理原语扫描器

扫描新写入的 CAD/Python 源码和几何清单中的：

- `make_box`；
- `Part.makeBox`；
- `Workplane.box`；
- 其他 AABB/OBB 代理生成调用。

发现 box 不应直接拒绝，而是要求：

- 当前对象已登记 `representationLevel=PROXY`；
- 输出路径属于代理命名空间；
- 存在 `refineByStage`；
- 不覆盖已验收设计实体；
- 当前 Gate 不把它作为设计几何验收对象。

#### B. 表示单调性检查器

在每次几何写入后比较新旧 `representation_registry`。任何等级下降、sourceRefs 减少或接口丢失都阻断。

#### C. 已验收构件覆盖保护

写入已有 `componentId` 前，必须提供：

- `supersedes`；
- 变更原因；
- 几何 delta；
- 受影响依赖；
- 新 revision 路径。

禁止原位覆盖 `accepted/`。

#### D. 逐构件回执

N04/G3 和 N07/G6 的总回执之外，为每个构件和子装配生成 `component_gate_receipt`。全桥总 Gate 只能聚合全部逐构件回执，不能用少数全局数字覆盖局部失败。

#### E. 多视图强制工件

阶段转换前必须存在：

- 固定相机 render manifest；
- 平面、立面、横断面和必要详图；
- 模型量测标注；
- overlay 控制点误差；
- 独立视觉评价；
- 未关闭问题。

#### F. 设计者与批准者分离

`createdBy` 与 `validator.id` 不得相同；视觉评价智能体不能使用建模智能体的隐藏推理或手工常量。

#### G. 最终代理清零 barrier

正式几何冻结要求：

- `proxy_count == 0`；
- 所有构件 `representationLevel == VERIFIED`；
- 所有接口通过；
- 所有关键 overlay 通过；
- 无退化；
- 无 CRITICAL/MAJOR 未关闭问题。

### 13.3 hooks 的边界

Hook 是执法点，不是视觉。它只能要求某个校验器运行并根据结果阻断；真正的“像人一样看装得对不对”需要独立的多模态评价工具和图纸 overlay 工具。

## 14. 推荐的最小智能体配置

不建议一开始构建大量并行智能体。推荐：

1. 一个确定性控制器；
2. 一个规划智能体；
3. 一个建模智能体；
4. 一个独立视觉评价智能体；
5. 一组确定性 CAD 校验工具。

建模和评价可以使用不同模型，或者至少使用隔离上下文和不同提示。规划智能体只在初始化和正式变更时运行，避免持续重写计划。

若后续需要并行化，只并行无依赖的构件工作包，例如左右锚碇、左右索塔的独立读取和建模。子装配合并、接口检查和全桥冻结仍由单一控制器串行完成。

## 15. 回归评测

模型版本从 5.5 升到 5.6，不能凭版本名称推断旧错误消失。应建立固定评测集，在每个模型、提示、工具和 hook 版本上重复运行。

至少包含以下案例：

1. 正确锚碇在后续阶段被 box 覆盖；
2. `4129.04 m` 被错误解释为多个不同参考面；
3. 桥宽被直接解释为主缆索面位置；
4. 吊杆下端错误落在桥面板顶面；
5. 全局跨度和宽度正确，但局部装配全部错误；
6. 代理体被写入设计几何；
7. overlay 只检查全局尺寸却声明通过；
8. 视觉上合理但精确尺寸错误；
9. 精确包围盒正确但轮廓、台阶或斜面错误；
10. 会话压缩后重新发明已经冻结的构件。

评测指标：

- 构件设计几何完成率；
- 代理清零率；
- sourceRefs 覆盖率；
- 接口闭合率；
- 控制点和轮廓 overlay 误差；
- 表示退化次数；
- 已验收构件被错误修改次数；
- 问题定位准确率；
- 反修循环收敛率；
- 无效放行率；
- 会话恢复后状态一致率。

最重要的指标不是“生成成功率”，而是“错误几何被放行的比例”。

## 16. 实施顺序

### 第一阶段：先建立流程和状态，不生成整桥

- 增加机器可读 `geometry_assembly_workflow.yaml`；
- 增加组件、接口、表示、代理和进度 schema；
- 增加表示单调性和覆盖保护；
- 为 PR #2 和 `STRICT-010` 建立回归案例。

### 第二阶段：实现两个确定性核心校验器

优先实现：

1. `representation_and_proxy_validator`；
2. `interface_coordinate_and_overlay_validator`。

前者防止盒子和版本退化，后者防止装配位置错误。

### 第三阶段：建立锚碇和桥面两个小型基准

不要立即重建整桥。先选择：

- 左锚碇子装配；
- 一段桥面—横梁—纵梁—吊杆接口子装配。

完整跑通代理、设计几何、量测、overlay、视觉评价、反修、冻结和退化测试。

### 第四阶段：扩展至全桥线性装配

按 S03–S11 逐阶段扩展，保持每个构件工作包可独立重放。

### 第五阶段：几何冻结后再连接 N08 以后流程

在以下条件全部满足前，不接入属性、边界、找形、荷载和求解：

- 代理清零；
- 全部构件达到 `VERIFIED`；
- 装配接口闭合；
- 多视图回投通过；
- 无退化；
- 逐构件回执和全桥回执完整。

## 17. 方案验收标准

该方案完成的标志不是产生一座新桥模型，而是系统能够稳定做到：

1. 在一个长任务中自动连续完成多个工作包；
2. 每个工作包结束后有可恢复检查点；
3. 代理盒子只能作为代理存在，并在规定阶段自动形成反修任务；
4. 设计几何不会被代理体或低保真版本覆盖；
5. 每个构件通过独立确定性和视觉检查；
6. 锚碇、索塔、桥面、主缆和吊杆按真实接口装配；
7. 上下文压缩后不重新发明已冻结坐标和构件；
8. 错误构件被阻断而不是带病进入下一阶段；
9. 在固定回归集上，5.5、5.6 或后续模型均按同一指标比较；
10. 几何 Gate 未通过时，任何 FEM 入口都不可用。

## 18. 最终建议

本项目应采用“一个确定性控制器 + 少量职责隔离智能体 + 逐构件工作包 + 双层反修循环”的混合方案。

关键不是把长任务变短，也不是要求用户逐环节确认；关键是把一个长目标变成可以自动连续推进、但每一步都无法绕过验收的持久化状态机。

代理盒子可以保留，前提是它具有独立身份、明确用途、退出期限和不可放行属性。设计实体必须通过参数化操作、接口约束、CAD 内核量测、多视图回投和独立视觉评价逐步形成。已经验收的构件只能通过带版本血缘的正向细化更新，不能被后续整桥重生成退化。
