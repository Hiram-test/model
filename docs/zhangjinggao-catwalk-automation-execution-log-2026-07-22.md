## 1. 为什么记录这份日志

本日志记录一次从“只有十九个 Skill 的供应包和项目资料”到“完成真实三维 ANSYS MAPDL 静力求解并与既有资料比较”的全过程。重点不是展示程序能够运行，而是回答以下问题：

1. 实施前到底有什么，缺什么；
2. 中间做了哪些错误尝试，如何发现并纠正；
3. 十九个 Skill 是真的执行了，还是只生成了目录、JSON 和 schema；
4. 最终三维模型是否建对；
5. 哪些能力已经被证实，哪些仍未完成；
6. 后续继续自动化时，哪些经验必须固化为质量门。

## 3. 对话中暴露出的核心认知问题

前期最大的偏差不是程序错误，而是对“执行完成”的定义不一致。

一度把以下事实描述成“十九个 Skill 已落实”：

- N00–N18 均生成主工件；
- 19/19 工件通过 schema；
- MAPDL Pilot 能运行；
- Gate 台账可以输出。

用户随后连续追问“为什么是二维”“谁和谁的误差”“这种误差有什么意义”“为什么要冒烟”。这些追问是正确的，因为：

- schema 合法只说明 JSON 结构满足契约；
- 十九个任务包存在只说明编排层被物化；
- 二维等效索束的残差很小，不代表全桥三维模型正确；
- 不同构件族、不同端点、不同荷载口径之间硬算误差没有工程意义；
- “冒烟测试”只能验证入口是否可调用，不能回答模型是否建对。

从此将验收问题重新定义为：必须从施工图事实开始，真实建立三维模型，实际调用 ANSYS，先封存独立结果，再与 MCT、复核报告和既有 ANSYS 同类项比较。

## 4. 图纸自动化和来源边界

施工图入口完成了整册渲染、离线 OCR、页级证据定位和目录/实体页对账。最重要的发现是：

- 目录列有 MD1-06《猫道承重索长度及构造》；
- 实体页在 MD1-05 后直接进入 MD2-01；
- 因此 MD1-06 在现有图册中实际缺失。

这不是普通缺页。猫道索长度、线形控制或下料信息很可能就在该图，因此正式 G1–G3 必须保持阻断。

为验证执行链，后续允许使用明确标记的临时补充输入，但始终遵守以下隔离顺序：

1. 图纸事实与临时补充形成独立输入；
2. 禁止在封存前读取 MCT 初始力、无应力长度、完整节点坐标和结果；
3. 生成几何并封存；
4. 编译、求解并封存独立静力结果；
5. 封存后才读取参考资料进行比较。

该顺序避免用参考答案反向调参后再宣称“独立验证”。

## 5. 失败运行和纠正记录

失败记录没有删除，因为它们是本次最有价值的自动化经验。

### 5.1 旧二维十九节点运行

旧统一运行器确实顺序执行了 N00–N18，生成十九份主工件和十九份任务包，schema 校验为 0 error。但 N07–N13 的核心几何、边界、找形、荷载和网格来自二维等效索束。

纠正后的结论：**旧运行证明十九节点运行时和 schema 能贯通，不证明全桥三维工程模型已完成。**

### 5.2 `RUN-ZJG-FULL3D-DRAWING-GEOM-001` 被拒绝

第一版三维几何错误地把主缆的 59.5 m、345 m、128 m、47.5 m 高程以及 255.56 m 垂度直接当成猫道控制线。

纠正措施：

- 主缆控制与猫道控制分开存储；
- 重新建立猫道支点高程；
- 将第一版运行写入拒绝说明，不再用于后续求解或比较。

### 5.3 `RUN-ZJG-FULL3D-STATIC-001` 被拒绝

第一版静力编译中，`H=w/(2k)` 的单位换算错误使初始水平力放大约 1000 倍。

纠正措施：

- 明确统一采用 N-mm-MPa-tonne-s；
- 将 N/m 换成 N/mm 后再代入曲率；
- 求解前检查力数量级；
- 保留该运行的拒绝说明，不覆盖或伪装成成功结果。

### 5.4 初始后处理结果被撤回

主求解完成后，第一次 `solution_summary.csv` 使用了不适用的聚合 `*GET`，得到接近 `0.78886E-30` 的无效数值。

纠正措施：

- 用 `*VGET` 读取全部节点和 LINK180 结果；
- 用 `*VSCFUN` 求位移和轴力包络；
- 生成 `solution_summary_corrected2.csv`；
- 旧文件保留，并附后处理纠正通知，避免无证据覆盖。

### 5.5 不同构件族的错误比较被撤回

一度把独立模型全部 LINK180 的最小力 43.655 kN 与既有承重索最小力 519.780 kN比较。后来确认 43.655 kN 来自扶手索，两者不是同一构件族，比较无意义。

纠正措施：

- 单独提取底部承重索和门架承重索轴力；
- 底索只与底索比较，门架索只与门架索比较；
- 不再把既有模型含下拉/特殊索单元的 1573.132 kN 最大值硬套给普通底索。

## 7. ANSYS 是否真的执行

答案是“是”。本次实际调用 ANSYS MAPDL 2026 R1 批处理求解，而不是只生成 APDL 文件。

求解证据如下：

- 进程返回码：0；
- 主求解 MAPDL error：0；
- 非线性子步：7/7 收敛；
- 最终载荷时间：1.0；
- RST 文件大小：115,998,720 bytes；
- RST SHA-256：`4438fcb31070e225599a46c9e51bd1bf24cfc0cb396b28ff9145eac23b5ab5d8`；
- 更正后的位移、索力和反力后处理：0 error、0 warning；
- 全部 81,088 个 LINK180 最终为拉力；
- 竖向支反力合计 34,315.063 kN；
- 按本模型重力反算总质量 3,499.163 t，内部重力闭合。

因此，“模型有没有真的跑起来”的答案是肯定的。

## 9. 十九个 Skill 到底执行了多少

必须用三个不同口径回答，避免再次把不同层级混为一谈。

### 9.1 节点和 schema 运行口径

- N00–N18：19/19 均由旧统一运行器启动并生成主工件；
- 专业节点 N01–N18：18/18 均执行；
- 主工件 schema：19/19 通过；
- 该运行的计算内核仍是二维等效索束。

结论：**十九节点运行时真的执行了，但执行的是二维 Pilot 数据，不是本次完整三维模型。**

### 9.2 本次完整三维职责覆盖口径

本次对十九个职责都进行了重新判读，状态统计为：

- 无条件 `PASS`：4 个，N01、N05、N12、N14；
- `PASS_WITH_BOUNDS`：9 个，N00、N03、N04、N06、N07、N09、N11、N13、N15；
- 工程放行或对照验收 `BLOCKED`：6 个，N02、N08、N10、N16、N17、N18。

其中阻断不代表程序没有运行。例如 N02 成功发现 MD1-06 缺页，N10 成功执行独立初始状态并发现跨中高程不一致，N17 成功完成参考比较；它们因为发现了真实问题而阻断工程结论。

## 10. 模型到底有没有建对

不能简单回答“对”或“不对”，应分四层判断。

| 层级 | 判断 | 依据 |
|---|---|---|
| 三维拓扑与数量 | 基本建对 | 两幅猫道、索、扶手、横梁、142 榀门架和 12 道横通道真实入模，数量闭合 |
| 有限元和求解执行 | 建对并真实执行 | LINK180/BEAM188/MASS21 编译成功，7/7 子步收敛，结果可提取，反力与本模型重力闭合 |
| 设计线形和初始状态 | 没有建对 | 主跨跨中低 25.56 m，门架索线形和初始索力明显偏离参考资料 |
| 正式工程模型 | 未完成 | MD1-06、正式 E/面积、端部转索与下拉、鞍座摩擦、精确截面、风温和施工阶段不完整 |

因此本次模型的准确名称是：**完整三维自动化执行验证模型**。它不是二维冒烟模型，也不是已经通过设计复核的生产模型。

## 11. 资料和版本冲突

自动化过程中还发现以下必须登记的冲突：

- 最新施工图门架承重索为 φ54、12.2 kg/m；复核报告恒载表写 φ50；
- 最新施工图底索为 12.038 kg/m；复核报告为 11.989 kg/m；
- 由最新图纸单位质量推得的等效面积与 MCT 等效面积不同；
- 复核报告出现 `14628/16=1371 kN` 的算术错误，正确结果约为 914 kN，报告后文也使用约 914 kN；
- 端点名称相同不等于物理位置相同，锚固点、转索点和分跨点之间不得直接比较坐标或长度。

## 12. 这次对 Skill 设计的实际经验

1. `schema PASS` 必须与“工程 Gate PASS”分开显示。
2. 二维、等效索束或 Pilot 必须在模型名称、输出目录和发布状态中持续显式标记。
3. 图纸关键缺页不能被临时补充悄悄解除；补充资料只能创建非发布分支。
4. 主缆控制、猫道底索控制和门架索控制必须使用不同数据对象。
5. 找形输入必须进行量纲和数量级检查，特别是 N/m 与 N/mm。
6. 参考模型必须在独立结果封存后读取。
7. 比较前必须核对构件族、物理位置、端点和荷载工况是否一致。
8. 失败运行和无效后处理不应删除，应写拒绝或纠正通知。
9. “求解收敛”只说明当前有限元问题被求解，不说明物理输入正确。
10. 完整三维适配器必须正式接入 N07–N15，才能宣称十九 Skill 对三维模型形成一键闭环。

## 13. 下一步

如果目标是验证三维结果能够复现已有资料，应创建新的参考校准运行：

1. 输入复核报告表 1-5 和表 1-6 的底索、门架索独立控制点；
2. 输入报告或正式确认的无应力长度、金属面积和弹性模量；
3. 展开锚固点、转索点、塔顶分跨点和下拉点；
4. 使用与参考模型一致的恒载口径；
5. 逐步增加施工、温度和风工况；
6. 把完整三维工件正式映射到 N07–N15 schema；
7. 新建运行目录，不能覆盖本次独立封存结果。

若把复核报告控制点作为输入，后续运行可以验证 FEM 实现和结果复现，但不能再称为“线形完全独立验证”。

## 14. 最终结论

本次工作真正证明了三件事：

- 图纸事实能够自动转换成一套规模真实的三维 MAPDL 模型；
- ANSYS 能够被自动调用并完成可审计的非线性静力求解；
- Skill 能够发现缺页、输入冲突和参考差异，并阻止错误工程结论发布。

本次工作没有证明：

- 当前独立线形与设计线形一致；
- 当前模型能够用于施工签发；
- 完整三维适配器已经与十九节点统一运行器一键贯通。

最准确的项目状态是：**自动化执行能力已得到真实三维求解证明；工程模型对照尚未通过；十九节点完整三维一键集成仍待完成。**
