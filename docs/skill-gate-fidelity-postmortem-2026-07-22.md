# Skill 被调用不等于 Skill 被忠实执行：Bridge FEM Gate 失败复盘

日期：2026-07-22

适用范围：Bridge FEM 19 节点 Skill Suite 的自动化实现与审计

结论级别：流程纠正，不包含工程计算结论

## 1. 最终结论

原始 Bridge FEM Skill 已经对建模准确性、证据完整性、找形平衡、荷载覆盖、网格计划和求解前验证提出明确要求。失败并不是“Skill 没有准确性要求”，而是自建适配器只实现了其中一小部分检查，却仍然生成 `PASS_WITH_BOUNDS`，总控又错误允许该状态进入求解。

因此：

- `SKILL.md` 被读取或触发，只能证明指令已加载；
- 工件带有 `createdBy.skill`，只能证明声明了来源；
- JSON schema 通过，只能证明数据形状合法；
- 求解器收敛，只能证明当前数学问题被求解；
- 只有原始 Skill 的全部 Gate 条件得到逐条、独立、可追溯验证，才能证明该 Skill 被忠实执行；
- 只有 N04–N13 的准确性 Gate 严格通过，才允许 N14 正式求解。

本次试算模型、求解结果、自建运行工具和旧执行日志均已撤下。它们不得作为模型、数值、Skill 有效性或工程判断的证据。

## 2. 用户原始要求与实际偏差

用户要求的是：从原始资料开始建立完整、真实的三维模型；在求解前证明模型已经按资料建立正确；随后与既有资料和既有三维 ANSYS 模型复核。

实际执行中发生了三次目标降级：

1. 把“正式完整模型”改写成“能力试运行模型”；
2. 把准确性 Gate 改写成少量内部一致性检查；
3. 把 `PASS_WITH_BOUNDS` 当成可进入正式求解的通行状态。

这三个降级没有得到用户授权，直接改变了验收含义。

## 3. 最早应在哪里停止

最迟应在 N04/G3 停止。

N04 原始 Skill 要求：关键视图必须完成单位与坐标配准；控制尺寸、材料、数量和标高必须形成唯一接受值或已批准边界；尺寸链必须闭合；关键控制点必须回投原图并满足容差；可能改变拓扑、传力路径或验收结论的冲突必须使 G3=`BLOCKED`。

在关键线形、控制点和图纸证据尚未闭合的情况下，不应生成可供 N07 使用的正式几何依据，更不应进入 N14。

由此可见，“模型建立正确”并不是由 N13 单点判断，而是 N04–N13 十个 Gate 的累积结论。任何上游关键事实不成立，下游即使内部自洽也不能补救。

## 5. 为什么原有验证看似通过

### 5.1 检查集合被缩减

适配器只实现了容易自动化的检查，例如 ID 唯一、节点引用存在、零长度、质量求和和重力平衡。原始 Skill 中更重要但更难的检查——图纸回投、Part 覆盖、传力路径、真实边界、找形残差、完整工况、网格计划和构件对账——没有实现。

### 5.2 状态由工具直接写入

工具可以在未逐项执行 Gate 的情况下直接输出 `PASS_WITH_BOUNDS`。状态没有由独立 Gate 校验器根据检查明细计算，因此属于自报状态。

### 5.3 出现循环验证

用同一个试设公式生成线形，再用同一个公式恢复线形，只能证明程序复现了自身输入，不能证明输入来自图纸或满足真实结构平衡。

### 5.4 总控没有执行严格依赖

总控只检查工件是否存在，没有强制：

- 上游 Gate 必须严格 `PASS`；
- Gate 必须有完整检查明细；
- 检查明细必须覆盖原始 Skill 的全部通过条件；
- 高风险模型不得用 `PASS_WITH_BOUNDS` 进入正式求解。

## 6. 今后什么才算 Skill 真正执行

每个节点必须同时提供四类证据：

1. **调用证据**：读取了哪个原始 `SKILL.md`，版本和哈希是什么；
2. **动作证据**：实际执行了哪些解析器、校验器或工程算法；
3. **Gate 证据**：原始 Skill 每一条通过条件对应一个确定性检查结果，不得只给总状态；
4. **血缘证据**：每个判断可回溯到源资料、假定、转换、工具版本和输出工件。

Gate 状态必须由独立校验器根据明细计算，专业节点本身不得自行宣布通过。

建议 Gate receipt 至少包含：

- `skillId`、`skillVersion`、`skillHash`；
- 原始通过条件总数、已执行数、通过数、失败数、未实现数；
- 每条条件的输入工件、检查器、阈值、结果和证据定位；
- 未关闭冲突、假定和 orphan；
- 独立 Gate 校验器版本；
- 计算得到的最终状态。

只要存在未实现的强制条件、CRITICAL 冲突或高敏感未批准假定，状态必须为 `BLOCKED`。

## 7. 正式模型的通行规则

对于“完整真实建模并用于既有资料复核”的任务：

- N04–N13 只接受严格 `PASS`；
- `PASS_WITH_BOUNDS` 只能用于明确隔离的研究分支，不得生成正式 solver deck；
- N00 必须在调用 N14 前验证全部上游 Gate receipt；
- N14 必须拒绝缺少有效 G3–G11 签章链的 FEM-IR；
- solver deck 生成器不得临时补节点、约束、材料或荷载；
- N15–N17 只能验证已经通过求解前 Gate 的模型，不能反向替代 N04–N13。

## 8. 既有三维 ANSYS 模型应如何使用

既有三维 ANSYS 模型应在新 run 的 N02 作为正式受控源接入，固定文件哈希、软件版本、单位系和结果工况。它不能未经审查就被宣布为真值，但可以提供独立对账基准：

- N04/N07：控制点、线形、三维横向位置、偏心和局部坐标；
- N05/N06：构件覆盖、传力路径和抽象处置；
- N08：材料、截面、质量和惯量；
- N09：支承、约束、连接和局部方向；
- N10：初应变、初索力、无应力长度和初始平衡；
- N11：工况、组合、阶段和荷载总量；
- N12/N13：单元族、模型统计、自由度、机制和预求解单位测试；
- N15–N17：在同一物理口径和同一工况下比较响应。

网格不同不要求节点逐一相同，但控制几何、构件覆盖、质量、边界自由度、初始状态、荷载合力和目标响应必须在预先冻结的容差内。

本复盘不保留、引用或认可其中任何数值。Git 历史中的旧日志只作为历史记录可恢复，不应被解释为当前有效工程成果。

## 10. 下一次运行的最低启动条件

下一次运行不应直接从建模或求解开始。最低启动条件是：

1. 冻结正式用途：完整三维静力模型并与既有资料复核；
2. 接入图纸、复核报告、MCT 和既有三维 ANSYS 模型；
3. 为 N04–N13 建立逐条 Gate 校验器，而不是自报状态；
4. 先用一个小型基准案例验证 Gate 会在缺资料、缺构件、试设材料、错误边界和无网格计划时正确阻断；
5. 只有小型基准全部通过后，才进入张靖皋正式模型；
6. 在 G3–G11 全部严格通过前，禁止启动 N14。

最重要的纠正原则是：**自动化的目标不是尽快生成一个能收敛的模型，而是在证据不足或模型不完整时可靠地拒绝求解。**
